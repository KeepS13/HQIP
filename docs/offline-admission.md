# 控制服务失联时的节点许可

实现版本：`offline-admission-v1`，Windows 客户端 4.5.0。默认不为任何节点启用，新旧节点可并存。

## 授权与连接

控制端保留原来的短租约接口。启用的 Agent 使用 `POST /api/v1/agents/offline-grants` 获取父许可；许可占用一个连接名额，绑定订阅、节点、凭据摘要和 native session / subscription scope。期限为最后一次成功核验起最长 24 小时，同时受订阅和登录会话已知截止时间限制。

父许可由 `portal_leases` 保留名额和带宽，由 `portal_offline_grants` 保存版本、预算和补账状态。HY2 协议没有改变：Agent 向内核发放至多 120 秒的本地子租约。父许可期限内正常续约和同节点重连均由 Agent 执行，不需要中央连接列表可达。

Agent SQLite 的 `offline_grants` 保存父许可、子连接、已发放预算和累计用量；`offline_requests` 在发送请求前记录幂等键。账本使用 WAL / synchronous FULL，写入成功才能放行。请求重试沿用原幂等键，补报重试沿用原版本与完全相同的累计快照。明确拒绝、无效协议响应、TLS 校验失败均不允许使用缓存。

子连接正常结束时回收其尚未使用的本地预算。未收到最终计数的连接，即使确认 HY2 已停止，也仍保留已发放预算；系统不会估计实际用量或把不确定预算再发一次。Agent 重启后，只有确认内核实例变化，或者经过短租约的单调时钟保护期并确认稳定内核上已无该订阅连接，才允许替换未知状态的旧连接。原子账本和所有待补报记录必须保留；未确认的旧用量可能需要运维核对，不能通过删除 SQLite 文件解决。

## 流量与带宽

普通预留按当前未预留余额除以剩余名额分配。不限流量订阅不设普通流量总预算。`portal_emergency_usage` 单独保存每份订阅已用与预留应急流量，所有节点合计最多 1 GiB。应急预算只在控制服务暂不可达且已分配普通预算不足时可用；真实应急用量同时计入总用量。

在线恢复后先幂等补账、核验撤权和到期，再续期与补充普通预算。已有应急子租约在恢复时结束，以便重新通过普通预算准入；旧应急使用量不会归零。不会自动扣款。

带宽继续使用已有版本确认机制。离线节点保留原速率上限，新连接不能在旧节点尚未确认降速时取得这部分带宽。许可到期可释放名额和速率；流量预留必须有最终计数才能释放。

## 客户端

成功连接的订阅、节点、凭据摘要、规则哈希与截止时间保存在已有本机加密存储中。账户接口失联不再单独触发 120 秒暂停；保留原连接并继续退避同步。实际转发正常显示“已连接”，节点链路恢复中显示“恢复中”，账户用量保留最后同步时间。

手动断开与退出立即生效。重启后可手动连接原节点；离线切换在停止原连接前拒绝。许可状态与用量更新不属于传输配置变更，不触发重新应用配置。第三方仍使用原订阅链接与 HY2 凭据，复制凭据只能共享节点许可名额和预算，不能可靠识别为不同设备。

## 迁移与灰度

1. 备份数据库与配套密钥，先发布控制端。PostgreSQL 由迁移角色运行 `hqip migrate-offline-admission`；正常发布脚本在切换前完成此增量迁移。SQLite 随启动增量迁移，不重置用户、订阅、用量。
2. 升级试点 Agent，确认报告包含 `offline-admission-v1`。发放许可前保留新 SQLite 账本备份；不能降级到不理解该账本的 Agent。
3. 仅对试点执行 `hqip offline-admission --data-dir /var/lib/hqip-control --node NODE_ID --enabled=true`。命令使用正常应用存储环境，更新目标节点配置版本。
4. 升级 Windows 4.5.0，分别测试客户端失联、节点失联、双方失联，核对实际下载、重连、限速与最终累计用量，再逐批启用。
5. 停止发放执行相同命令并使用 `--enabled=false`。已有许可及补账能力保留至许可结束，不能直接清空预留或删账本。发布兼容性检查拒绝不支持离线账本的控制端回退。

在控制服务失联期间新发生的撤权，最迟在恢复核验或原许可到期时生效。24 小时是授权上限，预算先耗尽则提前停止。

## 验证入口

- `go test ./...`：兼容性、模拟时钟、重启、竞争、预算、补报、客户端取消竞态。
- 指定本地 `HQIP_TEST_POSTGRES_URL` 后执行 `go test ./internal/store ./internal/control`：真实 PostgreSQL 事务与迁移，测试各自使用独立 schema。
- 设置 `HQIP_E2E_CORE`、`HQIP_SINGBOX`、`HQIP_MIHOMO`，执行 `go test ./internal/agent -run TestOfflineRealHY2 -v -timeout=5m`：真实两节点和两种客户端，控制 TCP 完全断开超过 125 秒、同节点重连、跨节点拒绝、撤权和精确最终补账。
- 设置 `HQIP_SINGBOX_EXE`，执行 `go test ./internal/client -run TestPinnedCoreRecoveryIntegration -v`：固定版本内核与生成配置的实际转发/恢复；加 `HQIP_RECOVERY_TUN=1` 使用隔离的 `/32` TUN 路由，不替换默认路由。此内核测试与控制服务故障测试分开执行。
- `python -m unittest discover -s scripts -p 'test_*.py'` 与三个前端构建：迁移角色、回退约束、构建和界面状态。
