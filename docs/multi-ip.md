# 服务器、多 IP 节点与 Cloudflare 运维

HQIP 按“服务器 → 公网 IP → 节点 → 设备授权”管理。一台 VPS 可安装多个独立 Hysteria 2 节点；每个节点绑定自己的入口 IPv4，并以同一 IPv4 建立代理出站。管理网站仍由正式控制服务器承载，不需要启动已退役的本地控制面或 SSH 隧道。

## 添加服务器与第二个 IP

1. 在 VPS 厂商控制台申请并配置新公网 IPv4，并按厂商说明把地址配置到 VPS 网卡。HQIP 不购买或解绑 IP，也不修改网卡、默认路由或厂商账户。
2. 在“服务器”中填写名称、SSH 管理地址、端口、用户和本次检查密码。默认 `root:22`。登记只验证主机身份、系统和权限，不安装 HY2。
3. 在该服务器的 IP 清单登记公网 IPv4。首版要求地址直接绑定本机接口；只通过 NAT 映射的公网地址不支持。SSH 管理地址可以与节点地址不同；更换管理地址仍必须匹配原 SSH 指纹与 machine-id。
4. 新建节点时选择服务器、已登记 IP、端口及域名方案；同一服务器的多个 IP 可分别使用 UDP 443。后台检查地址绑定、源地址出站、系统、端口和部署归属。
5. 节点通过 TLS、UDP、HTTPS 代理与出口 IP 检查后，再在设备页明确分配。一个设备获授权 IP-A，并不自动获得同服务器 IP-B。

同一服务器的安装、接管和 SSH 清理任务串行。每节点使用独立配置、账本、鉴权端口、统计端口及设备密码；共享的是不可变的固定版本二进制文件。服务器 CPU、内存、磁盘显示最新一份主机指标，不能把多个节点的主机资源相加。

## Cloudflare 设置与续期

在 Cloudflare 创建 Custom API Token，权限设为 `Zone:Read` 和 `DNS:Edit`，资源限定为准备给 HQIP 使用的 Zone。不要使用 Global API Key，也不要把 Token 填入节点 SSH 密码栏。管理员在“域名与证书”页面填写 Token、默认 Zone 和 ACME 联系邮箱，先验证再保存。替换 Token 时应覆盖现有节点使用的全部 Zone，否则旧域名的续期或清理会失败。

Token 加密保存，接口不回显，Agent 不接收 Token。自动域名采用随机 `n-….example.com`，为对应节点创建一个 **DNS only（灰云）** A 记录。普通 Cloudflare HTTP 代理不能转发 HY2 UDP；不要手工改成橙云。

Cloudflare 模式由控制服务执行 Let's Encrypt DNS-01，并清理本任务创建的 TXT。它不占节点 TCP 80/443；每节点使用独立证书、私钥及版本，Agent 验证后原子切换。证书签发和节点应用是不同状态：节点离线时新证书可能已签发，但仍“待应用”。每日续期检查遵循 ACME 建议窗口，失败重试并显示到期提醒。此处续期是 TLS 证书续期，域名注册商的购买续费仍由域名持有人处理。

手工域名可继续使用 HY2 HTTP 自动续期，需保持该节点 IP 的 TCP 80 可达且无冲突；AAAA 记录和其他错误解析会使检查失败。已有手工域名也可在重新部署时显式改为 Cloudflare DNS 证书模式：仅委托 `_acme-challenge`，不把已有 A 记录变成 HQIP 可删除资源。控制网站自己的 Nginx/Certbot 独立运行。

不要手工改动由 HQIP 创建的节点 DNS 记录。后台按 Record ID、类型、内容和归属校验后才删除；发现外部改动时会保留记录并提示处理，不覆盖其他业务域名。

## 接管已有 HY2

`owner-conflict` 表示安装归属不匹配，不能通过删除 owner 文件或跳过检查来修复。在原节点记录上输入 SSH 密码并运行“预检”，检查识别出的服务、路径及接管提示，再执行接管。预检结果有时效，远端状态改变后需重新检查。

可接管旧 HQIP 或独立 systemd HY2。接管前在节点 `/var/backups/hqip-nodes/` 创建受限备份，保存配置、证书、账本、服务状态及二进制信息。接管会把原来监听所有 IP 的实例迁为绑定所选 IP 的实例，并更换控制鉴权；旧连接密码不会继续授权。共享 H-ui、容器或无法确认归属的服务会阻断自动接管，应先人工拆分，不能停整个共享服务。

安装失败时先停止新实例，再恢复原配置及原启停状态；原来停用的旧服务不会为了回滚而被重新开放。原备份保留，部署日志显示位置。仅进程运行不代表验证通过；状态为“待外部验证”时仍需真实外部代理验收。

## 更换被封 IP 与删除

先添加新 IP、部署新节点并验证，再调整设备授权和默认节点，最后删除旧节点。客户端关闭代理时只保存新配置；开启时自动切换。新默认节点不可用会停止代理并恢复系统网络设置，不回退旧 IP、不自动选择其他节点。Clash 继续使用设备订阅，刷新时机由 Clash 自身决定。

节点删除确认页显示受影响设备。删除其默认节点且仍有其他授权节点时，必须明确选替代默认节点；没有剩余节点时下发空配置。并发修改返回冲突，应刷新确认页后重新选择。设备删除立即撤销账号会话、订阅和节点授权；所有删除均保留历史计量映射，断网补报仍归属原设备。

受管节点先拒绝鉴权、清理连接、上报最后用量，然后停止本节点服务并清理活动配置。Agent 失联或版本不支持时保持“待停止/待同步”，不能因 DNS 已删除就认为服务已停；可在节点详情提供 SSH 密码执行清理。删除一个 IP 节点不停止兄弟实例、不删除共享二进制、不改网卡。没有取得部署归属的失败记录仅删除管理记录。

节点清理完成后，该 IP 仍在服务器清单，可再次安装；新安装使用新节点 ID 和密码，必须重新分配设备。只有不再被节点引用的 IP 才能从清单删除；服务器也必须先完成所有节点的清理。

## 服务位置与故障排查

节点 ID 可从详情页取得。当前独立实例采用以下路径和服务名：

| 项目 | 位置 |
| --- | --- |
| Agent / HY2 服务 | `hqip-agent-<节点ID>.service` / `hqip-hysteria-<节点ID>.service` |
| 配置与归属 | `/etc/hqip-nodes/<节点ID>/` |
| Agent 账本、证书与 HY2 状态 | `/var/lib/hqip-nodes/<节点ID>/` |
| 不可变二进制 | `/opt/hqip-node/releases/<SHA-256>/` |
| 接管与回滚备份 | `/var/backups/hqip-nodes/` |

`systemctl status` 可查看具体实例；`journalctl --namespace=hqip -u hqip-agent-<节点ID> -u hqip-hysteria-<节点ID>` 查看对应日志。不要把配置文件、私钥、数据库、订阅链接或 Bearer Token 复制进公开日志或 Git。

界面中的“代理流量”是节点代理计量，不等于厂商账单。主机离线超过 30 秒，在线情况为未知；不能把失联期间的零值当成没有连接。

## 升级、备份与回退

升级前使用 `hqip backup` 导出数据库和配套主密钥，验证归档可读取，并保存当前控制二进制、前端产物、固定节点产物及 systemd 配置。备份放在受限目录，绝不进入 Git。正式站使用 `/var/lib/hqip-control`，部署文件位置见 [服务器部署与恢复](server-deployment.md)。

本版本数据库迁至 schema 3，为已有节点补服务器/IP 清单、生命周期及独立任务信息。节点 ID、设备授权、订阅、凭据和流量保留。只凭相似地址或可能来自克隆镜像的 SSH key 不自动合并服务器；旧实例在升级 Agent/接管前继续标为旧安装版本。

现有 Nginx 主机的后续发布使用 `scripts/upgrade_control.py`，不重新运行初次建站脚本。发布目录必须包含完整提交 SHA 和每个文件摘要的 `release.json`。脚本先校验新旧发布包，再停止控制服务，冷备份数据库、WAL、主密钥和服务配置；两路健康检查失败会自动恢复成对数据和旧二进制。示例（以实际发布目录、独立备份目录替换）：

```sh
python3 upgrade_control.py verify --release /opt/hqip-control/releases/COMMIT_SHA
python3 upgrade_control.py upgrade --release /opt/hqip-control/releases/COMMIT_SHA --state /root/backups/hqip-control-RELEASE
# 必须先恢复升级后已接管的节点，再执行控制面回退：
python3 upgrade_control.py rollback --state /root/backups/hqip-control-RELEASE
```

升级备份包含 `data.before`、`config.before.tar.gz` 和 `state.json`。失败后的新数据库会另存为 `failed-data-*`；不要用旧数据库直接覆盖仍运行的新进程。原 Nginx 和其他应用不参与此升级。

**旧控制程序不支持 schema 3，回退必须同时恢复升级前数据库与同一备份的 master.key，不能只换旧二进制。** 停止新控制进程后，在隔离目录验证配套备份，再恢复旧版本，始终只运行一个控制中心。若升级期间已经接管节点或改变凭据，还必须按节点接管备份恢复对应配置；只恢复控制数据库会造成控制状态和节点状态不一致。恢复之后重新确认 Agent 心跳、授权回执、客户端配置和用量补报。

真实多 IP 验收需要厂商已经配置好的两个公网 IP，检查 A/B 的入口和出口、凭据隔离及删除 A 不影响 B。单 IP 测试或使用不同端口不能证明双公网出口能力。
