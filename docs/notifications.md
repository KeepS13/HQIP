# 飞书机器人告警与提前提醒

在管理员后台的 **告警与通知**（`/admin/notifications`）配置一个飞书群自定义机器人。功能仅由控制服务执行，无需更新节点 Agent 或 Windows 客户端，也不改变套餐限速、流量额度及并发执行方式。

## 配置与首次测试

1. 在目标飞书群中进入群设置，添加“自定义机器人”，复制其 Webhook 地址。仅支持 `https://open.feishu.cn/open-apis/bot/v2/hook/...`，不支持 Lark 域名、代理地址或自建转发服务。
2. 在该机器人的安全设置中启用 **签名校验**，复制签名密钥。
3. 在 HQIP 后台打开 **告警与通知 → 机器人设置**，填写 Webhook 和签名密钥并保存。两者均加密保存，保存后不会回显原值；后续可分别替换。
4. 点击 **发送测试消息**。测试使用已保存配置，自动通知关闭时也可以测试；每 30 秒最多一次。测试先进入持久队列，后台显示投递进度；成功状态为 **飞书已接收**。请同时在目标群内核对消息。
5. 在 **通知类型** 中选择所需类别，然后启用自动通知并保存。所有类别默认选中，总开关默认关闭。首次启用会合并汇总当前异常，不补发完整历史事件。

若启用了飞书“自定义关键词”，请加入 `HQIP`；固定通知卡片包含该关键词。若启用 IP 白名单，允许控制服务器实际访问飞书时使用的公网出口地址。Webhook 所属机器人应同时启用签名校验。

同一页可以继续编辑设置，定时刷新只更新运行状态，不覆盖未保存输入。若另一个管理页面已保存更新，会提示版本冲突；选择“重新读取设置”，核对最新值后重新编辑。不要在日志、截图、工单或 Git 中保存 Webhook 完整地址与签名密钥。

停用或更换 Webhook 会取消旧待发任务；重新启用按当前状态生成提醒。清除凭据需要确认并保存，清除后自动通知停用，已有投递历史保留。取消某个通知类别会在发送前排除不再允许的提醒。已发往飞书的请求无法撤回，配置变更期间已在途的消息仍可能送达。

## 通知范围与计量口径

| 类别 | 触发条件 |
| --- | --- |
| 系统告警 | 已部署活动节点心跳中断 60 秒，或内核连续异常 60 秒；安装、验证、清理任务最终失败；同服务器有效报告显示可用磁盘不足 512 MiB |
| 容量提醒 | 服务器或节点按北京时间自然月累计流量达到 80%、100%；无限额度跳过，仍仅提醒、不限速、不断网 |
| 节点证书 | 到期前 14、7、3 天及已过期；签发、续期、应用失败 |
| 用户套餐 | 本次开通已确认上传＋下载达到 80%、90%、100%；到期前 7、3、1 天及已到期 |
| 恢复通知 | 已通知的运行异常恢复后通知一次；节点健康需稳定 30 秒 |

套餐流量为本次开通的一次性总额，不按月清零。待结算的流量预留单独显示，不当作已确认消耗触发“已用尽”。无限套餐不发流量阈值提醒；未开通或已停用用户不发到期预告。

到期日调整、套餐重新开通和月份变化分别建立对应的提醒周期；套餐普通修改不重置本次开通用量。一次检查跨过多个阈值时只发送当前最高等级。每个周期的同一阈值只提醒一次，持续运行异常每 6 小时最多重复提醒一次。

通知使用固定中文卡片，包含等级、对象、原因、用量或截止时间、北京时间、稳定事件编号及后台详情链接。用户邮箱遮罩，不包含 SSH 信息、密码、连接凭据、订阅链接、原始部署日志，不默认 `@所有人`。后台链接仍需管理员登录。

## 签名与可靠性

HQIP 是发送方，飞书是校验方，**不需要创建公网回调接口**。签名按[飞书官方自定义机器人文档](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)计算：

```text
timestamp = Unix 秒时间戳
key = timestamp + "\n" + secret
sign = Base64(HMAC-SHA256(key, 空消息))
```

`timestamp`、`sign` 与消息体一并提交。每次重试重新计算时间戳和签名。注意 HMAC 的消息为空，不能误将时间戳和密钥作为消息。控制服务器时间应保持同步。

仅允许标准飞书 HTTPS 地址；投递拒绝重定向与非公网目标。HTTP 200 不代表成功，只有飞书业务响应 `code == 0` 才记录“飞书已接收”，这也不代表群成员已读。

控制服务每 30 秒核对状态和到期条件，任务终态与业务事务一并记录。事件、去重状态和队列存入 SQLite；网络投递在事务外执行，最长 10 秒，每秒最多一批，突发提醒合并。网络故障、限流和服务端错误在初次尝试后最多重试 5 次，基础间隔为 30 秒、2 分钟、10 分钟、30 分钟、2 小时，另附加最多 10% 抖动；签名、白名单等配置错误需修正配置后人工重试。

每次发送前重新检查事件是否仍然有效，过时事件取消。投递记录保留 90 天，待发队列上限 1,000 条，避免无界增长。网络超时可能表示飞书已接收但响应丢失，再次发送可能重复；请以稳定事件编号识别，系统不承诺严格只发送一次。

控制服务完全停机时无法发送通知，重新启动后汇总当前状态。需要及时获知控制服务器自身停机时，应另配外部监控服务。此模块不提供手工维护公告。

## 常见问题

| 现象 | 排查方式 |
| --- | --- |
| 不能启用 | 必须同时保存有效 Webhook 和签名密钥；不要将 Cloudflare DNS Token 或 Turnstile Secret 填入此处 |
| 签名校验失败 | 核对机器人安全设置、当前签名密钥和控制服务器时钟；密钥更新后在 HQIP 替换保存，再测试 |
| 关键词或 IP 白名单拒绝 | 确认关键词包含 `HQIP`，白名单包含控制服务器的实际公网出口 |
| 地址不存在或机器人失效 | 确认群中机器人仍存在，重新复制其 Webhook 并在后台替换保存 |
| 测试提示过于频繁 | 等待 30 秒后重试；不要连续点击，以免触发飞书群机器人限流 |
| “等待重试” | 查看下次尝试时间；网络、限流和服务端异常会退避重试 |
| 飞书已接收但没有看到消息 | 核对 Webhook 对应的目标群、机器人状态及群消息，不要将接口接收成功理解为已读 |
| “已取消” | 事件已经过时、通知被停用、类别关闭或 Webhook 已替换；这是保护性取消，无需补发旧事件 |
| 设置冲突 | 先重新读取最新配置，再核对提交；不自动覆盖其他页面修改 |

投递记录中的“重试投递”只对仍然有效的失败事件开放。自动通知关闭时，普通通知不能重新投递；测试消息可使用已保存的凭据单独测试。

## 备份与恢复

通知配置复用现有主密钥。备份时必须保留**一致性数据库与配套主密钥**；只恢复数据库无法解密凭据。事件、尝试次数与去重状态随数据库恢复。恢复旧备份可能使备份之后的外部投递状态无法完整还原，因此可能重复通知，应结合稳定事件编号核对。

回退前先停用自动通知，保存数据库与主密钥。本版通知迁移为增量表结构，回退只切换程序，**不以旧快照覆盖当前数据库**，以免丢失回退前的新账号、额度消耗及连接结算。不要为排查消息问题修改计量账本、节点授权或用户套餐。

在控制服务器以 root 执行以下命令，将 `--state` 的参数替换为本次部署实际输出的备份目录，不能选用其他发布的快照：

```bash
python3 /opt/hqip-control/releases/<本次发布提交SHA>/scripts/upgrade_notifications.py rollback --state /root/backups/<本次通知发布备份目录>
```

该脚本依据 `--state` 中的升级记录恢复之前的程序路径，保留当前数据库和主密钥，并检查服务健康。备份内 `data.before` 仅供故障调查与协调恢复使用，不会自动还原到生产数据目录。

验证覆盖签名、HTTP 与飞书业务码、重试、去重、过期任务取消、权限和凭据脱敏；真实群测试需管理员配置有效机器人后在后台明确点击“发送测试消息”。
