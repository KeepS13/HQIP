# 服务器凭据、Agent 升级与发布连续性

在「服务器」新增服务器时，可以勾选保存 SSH 凭据。已有服务器进入详情页，在「SSH 凭据与自动运维」中验证并保存一次。后台仅返回凭据状态，密码通过现有主密钥加密后入库；数据库备份必须与原有 `master.key` 配对保管。更换 SSH 地址、端口、账号或机器身份后，需要重新验证凭据。

保存的凭据每小时检查一次，也可手动立即检查。认证失败、网络不可达、主机指纹变化分别显示；巡检能够发现失效，不会阻止外部改密或自动重置服务器密码。离线服务器会在后续周期重试。

「更新 SSH 密码」仅用于更新后台保存的凭据。先在服务器厂商处修改密码，再在此填写服务器当前密码；验证 SSH 登录及已登记主机指纹通过后，加密替换保存的密码。验证失败保留原记录。后台不能修改服务器账号的实际密码；旧远程改密及重试接口返回 410，历史未完成改密任务在启动恢复时终止并清除候选密码，不再执行。

「升级 Agent」可从节点详情、服务器详情或服务器列表发起，支持批量选择。后台校验发布版本、主机身份、安装归属与产物哈希，保留流量账本和配置，仅重启 Agent，转发核心继续运行。同一服务器上的任务串行执行。远端升级由 systemd 持久任务执行，控制端重启后按原任务编号读取回执，不因 SSH 断开重复执行升级。尚未保存凭据的服务器会提示补录，无法从旧的一次性密码记录恢复已清除的密码。

首次升级自动创建私有备份目录，无需预先手工升级。任务列表显示服务器或节点名称；远端回执区分备份路径、磁盘空间、运维锁、产物校验及 Agent 启动等失败，不回传原始命令输出或密码。失败任务可重新选择节点发起升级，旧记录保留供排查。

## 运行与发布

- PostgreSQL 由迁移账号显式执行 `hqip migrate-operations`，新增表，不清空用户、会话或账本。自动发布会检查并执行此步骤；应用账号不需要 DDL 权限。
- 发布先在线备份 PostgreSQL、检查磁盘和准备新增表，完成后再停止 API 切换版本。准备失败保留当前服务。在线备份是备份开始时的一致性快照；回滚仍保留当前实时数据库，不会恢复较旧快照覆盖新增账务。
- 后台数据库故障采用退避重试；所有权连接断开时先停止并等待原任务退出，再重新获取领导锁，API 不因后台任务错误退出。任务结束写库单独重试，不重放远程操作。异常和恢复记录在控制服务日志中。
- 清理每分钟执行，各表每轮最多 500 条、单表最多 2 秒，独立提交并记录失败。统计明细沿用 7 天/90 天/13 个月，事件 30 天，审计 13 个月。终结运维任务保留 90 天。
- 已过期刷新凭据及刷新回执到期清除；授权请求过期 24 小时后清除；客户端会话在刷新期限过期 30 天后清理。仍有有效刷新回执、未结束连接或旧客户端移除参与记录的会话继续保留，不删除流量账本。

## 客户端登录保持

数据库临时故障返回 503，不再被误判为无效登录。新客户端会在刷新前保存请求编号、刷新后立即保存新令牌；响应丢失时，可在 10 分钟内重试同一次刷新并恢复同一组令牌。不同请求重放、主动注销、撤销或真正过期仍会失效。已被撤销的旧会话需要重新登录一次。

这降低了正常迭代造成的退出和断线风险，不承诺零停机；需要长时间数据转换的版本仍应安排维护窗口。连接租约维持原有最长 120 秒，不延长授权或计费期限。
