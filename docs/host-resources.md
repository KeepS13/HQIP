# 控制台主机资源

管理端侧栏显示运行 HQIP 控制服务的主机 CPU、内存和服务数据分区容量。仓库正式部署配置将 Nginx 静态前端与控制服务部署在同一台机器；如果自行拆分部署，这里仍只代表控制服务主机，不代表浏览器、代理节点或所有服务器的合计。

`GET /api/v1/host-resources` 仅在管理员 API 上提供，要求已完成初始改密的管理员会话；公共和用户 API 不提供此接口。响应只包含采样时间、CPU 百分比、内存与磁盘的已用/总量，不包含主机名、文件路径或进程信息。

页面正常每 5 秒发起一轮读取，服务端最多每 5 秒触发一轮异步采样。同一轮并发请求共享工作协程，HTTP 不等待采样。CPU 是累计计数的差值；首次进入或暂停超过 20 秒后需要重建基线。过去要等待下一次 5 秒采样，且页面忽略 `refreshing`，常需再等一轮才看到 CPU。

现在同一工作协程遇到 CPU 未知时先发布内存/磁盘，间隔 1 秒补一次采样。页面遇到 `refreshing=true` 每 250 毫秒检查结果，最多持续 10 秒，随后退回 5 秒间隔。正常读取通常两次 HTTP 即可获取新结果；首次约 1 秒完成基线，具体受系统读取和网络耗时影响。CPU 源持续失败时每轮最多补采一次，不无限重试或伪造 0%。一个页面只允许一个在途请求，单请求 10 秒超时；隐藏/卸载时取消请求与定时器，重新可见立即恢复。没有常驻采样协程，页面关闭后至多完成已经开始的那轮采样。

CPU 必须取得两次间隔不超过 20 秒的有效累积计数才显示百分比；计数器重置、读取失败时保持未知，也不会把暂停期间的平均负载当作当前负载。真实的 0% 正常显示。

Linux 从 `/proc/stat`、`/proc/meminfo` 和数据目录所在文件系统读取；Windows 开发环境通过系统 API 获取相同指标。Linux 已用内存按总量减可用内存计算，磁盘按文件系统总块数减空闲块数计算，仅覆盖 `--data-dir` 所在分区，不合计其他挂载盘。容量使用 MiB/GiB/TiB。其他平台或无法采集的单项显示未知；请求失败或采样超过 20 秒时保留上次数据并明确标注过期。
