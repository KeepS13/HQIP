# 节点 IP 质量体检

管理端打开「节点管理 → 节点详情 → IP 质量体检」，可以查看此节点的出口 IP、ASN、网络组织、地区、各数据源的信誉评分、流媒体和 AI 服务可访问性，以及完整 JSON 报告。

成功部署节点后会自动检测。已有节点可点击「检测 IP 质量」或「重新检测」，重新输入本次任务的 SSH 密码。检测任务与同服务器的部署、接管和清理操作串行执行，使用已验证的 SSH 主机身份。每个节点的手动检测间隔至少 10 分钟，检测有时间上限；失败会单独显示，并保留上次成功报告，不将正常的 VPN 节点改为部署失败。

## 如何解读

- 报告对应节点的指定公网 IPv4。入口域名不用于选择检测出口；不会用服务器默认 IP 替代指定 IP。
- 地理位置、用途和风险评分来自不同第三方数据库，各有更新延迟及不同口径。界面保留各来源结果，不合成一个「节点总分」。
- 这份报告检测 IP 信誉与当时的服务可访问性，不代表从你的网络连接节点时的带宽、延迟、丢包或线路稳定性。
- 检测失败、空值和上游返回的 `null` 均视为未知；未知不能当作安全、未列黑或服务可用。
- HQIP 使用无特权检测环境，省略需要监听本机端口的 SMTP 探测，报告明确显示「未检测」。旧版邮件探测可能使用默认出口，不能据此确认一个多 IP 节点的邮件出站能力。
- DNS 查询失败单独列为未知，不计为已确认未列黑；未列黑也不能作为 IP 安全结论。旧版上游报告可能未区分 DNS 查询失败。
- 检测直接访问第三方服务，向这些服务暴露所测公网 IP；不会生成公开报告链接。检测请求不经过用户 VPN 代理计量，云厂商仍可能计入服务器账单。

## 数据与权限

报告及检测状态由控制服务保存，仅管理 API 可读写；不进入用户网页、客户端订阅或 Agent 配置。任务完成后删除短期 SSH 密码。页面每 5 秒刷新，刷新失败时保留最近数据并提示；旧报告不会冒充本次检测成功。

管理接口为 `GET /api/v1/nodes/{id}/network-quality`、`POST /api/v1/nodes/{id}/network-quality`。启动请求带 `password` 和节点 `expectedRevision`，沿用管理员认证与 CSRF 校验。

Ubuntu／Debian 节点缺少工具时，仅通过系统包管理器补装 `jq`、`bc`、`dnsutils`，不升级系统或修改网络配置；安装失败会显示依赖错误。检测以非特权账户运行，限制 CPU、内存和运行时长，结束后清理临时文件。

检测程序来自 [xykt/IPQuality](https://github.com/xykt/IPQuality)，遵循其 [AGPL-3.0 许可](https://github.com/xykt/IPQuality/blob/main/LICENSE)。[HQIP 适配源码与许可](https://github.com/KeepS13/HQIP/tree/main/internal/provision/ipquality) 随仓库提供。HQIP 固定并校验脚本版本，不直接执行重定向网址返回的任意新版本；节点报告保留来源版本，便于核对。
