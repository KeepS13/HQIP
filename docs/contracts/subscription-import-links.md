# subscription-admission.import-links

Owner: subscription-admission（internal/store、internal/control）

Version: 2（固定账户入口；兼容现有单份及旧合并快照入口）

Consumers: user-web、第三方 Clash/Mihomo、V2Ray、sing-box 客户端。

固定入口属于用户账户，与套餐数量和状态无关；无套餐、全部到期或待开通时仍可复制，导出 200 空节点配置。Clash/sing-box 仅允许恢复网站直连、其余拒绝，V2Ray 为零条 URI；不授予代理连接权限。购买、续费、更换套餐或开通后，在客户端更新原链接即可。复制页面单份选择器仅显示 `active`，隐藏 `pending`、到期、撤销、禁用与耗尽项；失效的显式选择不会自动改为其他订阅。

兼容的单份 `pending` API 仍可准备和读取空配置，见 [activation v1](../subscription-activation.md)；页面不再列出这类不可用单份。

## 请求与响应

- `GET /api/v1/user/subscriptions/{id}/import-link` 读取单份链接。
- `POST /api/v1/user/subscriptions/{id}/import-link` 幂等准备单份链接；`/rotate` 轮换；`/revoke` 撤销。
- 将以上路径的 `/subscriptions/{id}` 移除，操作范围变为当前认证用户的全部订阅。
- 浏览器接口要求用户会话；所有 POST 要求同源与 CSRF。返回 `{url: string}`，不信任调用者传入的用户 ID。
- 管理员 `POST /api/v1/subscription-import-links/prepare` 显式为所有现有用户补齐缺失的账户入口，要求管理员会话、同源和CSRF，返回 `{users,created,existing}`，不返回链接或秘密。包含无套餐及停用账户，但停用检查仍生效；已有账户入口、旧单份／快照及其凭据不变。单事务按用户ID顺序锁定并提交，重复执行不会轮换已有入口，不作为启动任务自动运行。
- GET 不创建凭据；账户入口尚未准备或已撤销时返回空字符串，已有入口不因套餐状态改变而消失。单份 GET 对失效订阅仍返回空字符串。
- 自动准备只发生在进入复制页面时。平时刷新为 GET；撤销后再次点击复制可以显式准备新链接。

## 合并语义与兼容

默认入口使用 `/usub/all.{userId}.{secret}`，256 位随机秘密加密保存在现有业务 metadata 的 `portal-account-import:{userId}` 项中，用户 ID 本身不授予访问权限。无数据库 schema 迁移。每次导出在同一事务快照内验证入口和用户启用状态，按 ID 读取当前有效／待开通成员；新购订阅不需要预先创建单份链接。只有显式轮换、撤销后重新准备才更换账户入口，单份轮换不改变它。

旧 `/usub/{token}` 单份及点分隔快照保持原解析语义，不会把旧单份权限扩大为账户权限。按用户最终确认的发布方式，保留旧链接可用，同时为所有用户准备新的固定入口；旧版只有一个套餐时「全部」与单份地址相同，需要重新复制新默认入口才能获得账户范围。旧版多份快照若要自动包含后续购买，同样需要复制新入口；继续作为单份／旧快照使用无需替换。各格式共用账户入口的路径，仅查询参数不同。

配置导出仍使用 `format=clash|v2ray|singbox` 和 `download=1`。合并中每份节点使用该份自己的凭据，并为节点标识和名称添加订阅标识，避免同名模板、同一服务器互相覆盖；计费、限速和在线名额仍按订阅实例隔离。失效成员不输出节点；固定账户入口没有可用成员时返回空配置，旧单份／快照全部失效仍返回 403。有效订阅没有合格自动节点时仍为 503，部分成员暂不可连接时可导出其他有效成员。

## 失效、事务与错误

轮换或撤销在一个事务中更新入口令牌、删除对应第三方凭据并撤销现有租约。写事务先锁用户，再更新订阅、凭据和租约；数据库冲突按既有重试策略处理。任一失败整体回滚，不产生部分轮换。

“全部”轮换／撤销覆盖账户入口、该用户全部第三方凭据和旧单份入口（包含已经失效的订阅）；新账户入口动态加载当前成员。单份操作只处理该份入口与凭据，账户 URL 保持不变，更新账户订阅可取得该份新凭据。旧快照只要有一个成员令牌被轮换、撤销或移除，整个快照返回 404，不回退到部分集合。

旧节点凭据不能建立新连接；正在转发的租约在节点下一次同步时撤权，可能存在网络同步延迟。待结算预留和账本保留到最终结算，原生 HQIP 会话及凭据不受影响。导出响应写出前再次验证全部令牌，避免在途旧 URL 获取轮换后的新凭据。

跨账户拼接、重复令牌、格式错误、停用账户和撤销链接返回 404；未登录为 401，CSRF 失败为 403，外部用户的单份 ID 为 404。失效单份创建或轮换为 403，仍可撤销；空账户允许准备和轮换账户入口。数据库错误不当作空订阅或部分成功。

## 规则模式（2026-11-23 修正）

Clash、sing-box 的完整配置及 HQIP 原生规则模式统一执行大陆域名和 IPv4/IPv6 直连，优先于保存的旧服务分组，其余自定义规则保持顺序。配置生成时组合内置快照，因此已有 LAN-only 包也生效；导出不写回规则历史、哈希或凭据。Clash 内联 CN 地址，不依赖客户端 Geo 数据库，并提供大陆 DNS 策略和保留目标地址的 HTTP/TLS 域名嗅探。sing-box 使用本地 DNS 做大陆域名及 IP 分类。

`format=v2ray` 保持 Base64 节点 URI 列表，不携带路由，不能自动修改 v2rayN、v2rayNG 或 Shadowrocket 的配置。它们需要在客户端选择大陆直连规则；全局模式或本地覆写不受服务器配置保证。真实验证版本、数据更新和其他边界见 [大陆分流](../mainland-routing.md)。

## 节点 DNS 与网站恢复（2026-11-26）

Clash 完整配置为节点域名提供独立的 `proxy-server-nameserver`（`223.5.5.5`、`119.29.29.29`）；海外 DoH fallback 经 `节点选择` 查询，不能在建立代理前依赖海外直连 DoH。官网、API、管理员站点从部署的 `PublicURL`、`UserOrigin`、`AdminOrigin` 提取精确主机名，并与登录所需的 `challenges.cloudflare.com` 一起置于规则最前，使用直连 DNS。仅 URL 本身是 IP 时输出 /32 或 /128，不解析并绕过共享 CDN 网段，也不放宽父域名。

sing-box 完整配置使用相同网站名单；待开通 Clash/sing-box 只允许这些网站直连，其余仍拒绝，不下发代理凭据。HQIP 原生客户端的官方域名名单与 Windows 系统代理例外同步，包含用户站、管理站和验证码；它们不属于授权来源白名单，不改变登录安全校验。

现有用户须更新并重新启用完整订阅；原生客户端须安装包含本次代码的新版本。直连使用用户实际本地出口，不能把境外网络变成大陆 IP。网站服务端不能覆盖其他代理软件、用户手动选择的 Clash 全局模式或第三方节点 URI 的路由；这些情况须在对应客户端添加直连例外。验证码走本地线路不保证其运营商在所有网络可达。

## 各客户端导入与恢复帮助（2026-11-26）

通用 `clash://install-config` 与 Verge 专用 `clash-verge://install-config` 将 `name` 放在前、编码后的 `url` 放在最后；Clash Verge Rev 2.5.10 会读取 `url=` 后的整个尾部，后置名称会污染订阅路径。选择 Verge 时使用其官方注册的专用 scheme，避免其他已安装 Clash 应用接管。CMFA 使用同样顺序的 `clashmeta://install-config` 并传递名称；v2rayNG 和 sing-box 保持 URL 查询参数加名称 fragment。v2rayN、Shadowrocket 保留复制后手动添加，不生成未经验证的唤起链接。

公共 `GET /api/v1/user/config` 增加 `directAccessHosts: string[]`，由 `ServiceBypassHosts` 从同一部署配置生成，只包含精确主机名/IP，不包含端口、路径或凭据。导入页面在用户首次展开恢复帮助时读取一次，关闭/切换订阅取消请求；15 秒超时后可重试，不新增轮询。仅在页面中展示和复制地址不代表客户端路由已配置成功。

节点 URI 的三个客户端须手动添加优先规则；v2rayN/NG 域名使用 `full:` 精确匹配并选择 `direct`，Shadowrocket 使用 `DOMAIN` → `DIRECT`，IP 地址使用 IP 规则。说明及验证范围见 [客户端兼容审查](../reviews/2026-11-26-client-compatibility.md)。

## 导出性能边界

最多合并 100 份有效／待开通订阅；超过上限拒绝，不截断。旧快照令牌段最多 4399 字节，账户令牌长度不随订阅数量变化。每次导出复用现有配置构建器；账户凭据与准入状态均按 metadata 主键查询。链接状态每 30 秒及页面重新可见时读取，同一页面不会重叠轮询；GET 只查账户入口，不枚举订阅、不构建节点配置、不发放节点凭据。账户用量沿用自己的刷新周期，不新增后台任务或数据库迁移。
