# subscription-admission.connection-slots

版本：connection-slots-v3。所有者：store 的订阅事务、Agent 的本地连接账本。节点数与同时在线上限保持独立，上限合计 HY2 客户端实例数与 VLESS 来源 IP 数，跨节点共享，完整计数定义见 [在线计数](online-ips.md)。

订阅凭据确定身份与套餐，父账本保存累计流量和已核验有效期；在线名额具有独立的申请/释放状态。网站返回 connectionSlotsVersion=3 后，新 Agent 才能通过累计报告中的 slotAction=release/acquire 启用该能力。旧 Agent 不自动释放名额，防止其未重新申请就复用已释放许可。

节点持有 offlineMu，先持久化结束状态和操作意图，再发报告。正常 final 立即触发同步和释放；异常连接由节点依据内核实例变化或最后一次子租约发放后经过完整的 120 秒单调时钟期限及 5 秒保护期判断结束。缺失 final 的获发流量继续保留，释放名额不能清空或估算这些计数。

中央在同一订阅事务中结算真实累计用量并处理名额变更。释放后 portal_leases.expires 不再占在线名额；原许可有效期独立保留在计费状态。释放同时将 bandwidth/ceiling 归零、pending 置位并推进速率版本，重新申请时必须先预留带宽再转发。重新申请先检查身份、套餐和全订阅在线上限；即使名额已满，也返回已经确认的真实用量和 slotReleased=true，不回滚补账。已撤销或用尽额度的账本也可释放已结束连接的名额，并继续接受迟到 final。所有版本重放保持原请求不变，不重复占用或释放名额。

网站失联时不把活跃连接当成离线。已持有名额的节点继续按原许可、余额和倍率服务；已释放的名额必须重新得到网站批准，不能离线复活。失联期间的正常断开先记录在本地，通信恢复后立即补报并释放。恢复后的超额或撤销结果在节点下一次续约时停止转发。

授权报告回执与转发许可分别校验：管理员缩短有效期是合法的控制端变更，不能因截止时间变早拒收回执。已提交报告的幂等回执即使到达时已过期，也必须确认原累计用量和版本，随后上报断开或释放；过期回执本身不能授权转发。身份、协议、用量及报告版本仍须严格匹配，待确认报告不能被改写。旧版因此留下的 denied/pending 记录在升级后原样重放并正常结束，不需要删除租约或计费账本。

首次准入的回包丢失、被截断或收到前节点重启时，`offline_requests` 中的原请求 ID 必须保留。后台通过节点鉴权的 `POST /api/v1/agents/offline-grants/recover` 查询已提交回执，请求体只有 `connectionId`，不保存或重传明文订阅密码；该接口不新增、续期或重新占用名额，凭据轮换、撤销及过期后仍可用于结算。404 仅表示本次未查到（也可能是旧控制端或原事务尚未提交），不能据此丢弃请求。首次明确的 4xx 拒绝（408/429 除外）可以移除请求；已有不确定结果的重试被拒绝时仍须恢复原请求。

恢复时核对节点、凭据哈希、协议与来源 IP。只有本地从未保存父账本、中央报告版本与用量均为零的回执，才能创建禁止转发的本地记录并通过正常 final 归零名额。本地已有父账本时仅移除陈旧请求标记，不能覆盖其子连接、计数或未知预算；客户端重试也遵守此规则。中央已有报告而本地缺少账本时保留请求并拒绝猜测用量。初次回执已过期也可进入结算，不能用于转发。节点退役前须确认待恢复请求已处理，不能因父账本列表为空丢弃它们。

周期同步仍使用四秒总预算，按待报告重试时间从早到晚处理，避免每轮从固定 ID 开始导致后面的断开记录一直无法清理。首次回执恢复最多每三十秒查询十六条请求，按请求键轮转，最多占用当前同步剩余预算的一半；其失败不能阻断已知连接的 final/release。队列容量沿用节点账本上限，不淘汰未确认记录。这是兼容的恢复端点扩展，无数据库迁移；须先部署控制端，再部署 Agent 才能启用自动恢复。

发布顺序为控制端、节点 Agent 与 HY2 内核。旧内核不提供来源 IP，升级过渡期新准入会被拒绝；仅升级 Agent 不足以启用该功能。增量迁移即记录业务契约版本，发布与回退检查必须拒绝不理解该状态的旧控制端/Agent。Agent 账本中的已释放、待确认操作、版本标记均触发旧版拒绝；停止 Agent 前后各检查一次，禁止恢复旧账本。节点汇报 connection-slots-v3，发布包与节点包均声明 connectionSlotsVersion=3。操作证据保存在库外，不写入业务数据库。

验证入口：store/agent 的 TestOfflineSlot 系列覆盖单名额、并发抢占、满额补账、丢回执重启、逐连接超时、撤销与迟到 final、失联重连边界；TestConnectionSlotsRealTwoNodeSwitchAndReconnect 使用真实客户端和双节点验证退出、切换与返回原节点。部署兼容性测试见 scripts/test_connection_slots_deployment.py。

`TestOfflineRecovery*`、`TestOfflineRequestFailure*` 和 `TestOfflineSweepDoesNotStarveLaterIdleSlots` 补充首次准入丢回包后无人重连、半写入崩溃、晚提交、截断回包、身份不匹配、丢失本地用量、恢复超时隔离与同步公平性；控制端测试核对节点鉴权及恢复前后真实占用数。
