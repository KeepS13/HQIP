# node-network v1

Owner: `node-provisioning` (`internal/provision`), Agent 网络配置与升级脚本。Consumers: 管理员预检、部署/重部署、HY2、VLESS/Reality、Agent 更新及退役。

节点的 `publicIp` 始终是订阅、DNS、外部验证和安装归属所使用的公网地址。服务器本地 `agent.json` 的可选 `bindIp` 保存内核实际拥有的 IPv4；缺省回退 `publicIp`，兼容已有直连公网节点。它不是新的节点或业务身份，不写入控制数据库，不改写公网地址记录。

预检优先选择直接配置在网卡的公网地址。不存在时，读取路由选定的本机 IPv4，并通过绑定该源地址的 HTTPS 请求验证公网出口；源地址必须确实存在于网卡，且出口必须等于所选 `publicIp`。失败、空值、不同公网出口均拒绝自动部署，不退回通配监听，也不自动添加 IP、改路由或配置供应商 NAT。仅 NAT 候选增加一次最多 8 秒的出口查询；无目标 IP 的服务器检查和直连 IP 预检不新增外部查询。

管理员预检响应增加可选 `bindIp`。端口冲突、原生 HY2 接管检查、HY2 监听/出站、HTTP 证书验证监听、Reality 监听/握手目标/独立出站及 UFW 规则统一使用该本机地址。安装归属、凭据、域名、账本及外部代理验收继续使用原公网身份。执行阶段持有既有主机锁，重读网卡与映射，并在停止旧服务前再次验证源地址到公网出口；快照中的映射变化要求重新预检。

节点发布清单 `nodeNetworkVersion=1` 表示 Agent 支持该配置。NAT 部署和 Agent 升级必须使用兼容产物；不兼容升级在停止服务前拒绝。Agent 单独升级保留 `bindIp`、Reality 密钥与端口、核心运行实例及账本，升级失败恢复原配置。重新部署重新识别本机地址；NAT 出口观察失败不影响现有节点运行，也不阻止凭固定安装归属进行退役。

支持公网与内网同端口映射且所选本机地址出口等于节点公网 IP 的 NAT。供应商须提供所需入站端口：HY2 使用节点 UDP 端口，Reality 使用实际 TCP 端口；HTTP 证书验证另需 TCP 80，DNS 验证不需要。纯出站共享 NAT、未开放的入站映射、非对称公网出口以及外部/内部端口不同的映射不在自动识别范围。出口检测不能证明入站可用；部署必须通过既有公网 TLS、QUIC 与代理出口验证，否则按原机制回滚。

无数据库迁移、无前端轮询、无新常驻进程。操作证明仅保存在文档或库外诊断记录。
