# subscription-admission.template-apply

Owner: subscription-admission（internal/store、internal/control）

Version: 2

Consumers: admin-web；用户站、原生客户端和第三方导出读取同一份分配与模板限制。

## 请求与响应

管理员先保存套餐，再在订阅管理卡片点击「立刻应用」。`POST /api/v1/subscription-templates/{id}/apply` 携带 `{expectedRevision}`，只应用这个已保存版本。要求管理员认证、同源及 CSRF；用户会话不能调用。版本过期为 409、不存在为 404，事务失败不返回部分成功。

成功返回 `{affectedSubscriptions, updatedSubscriptions, allocationShortfalls}`。前者为该模板尚未到期／移除的实例数（包含待开通、停用、流量耗尽实例）；后者为节点集合或分配目标实际发生变化的实例数。缺额项沿用 `{userId, subscriptionId, required, assigned}`，响应明确告知实际分配不足，不能把缺额当作完整成功。

## 应用规则

- 自动实例的 `target_count` 改为已保存的 `nodesPerSubscription` 与非空候选池大小的较小值；配置数允许超过选择数，并保留原值。配置10、选3个时分配全部3个，不产生人为缺额；健康或占用不足仍报告真实缺额。自动实例保留池内原节点，缩容按已保存顺序保留前 N 个，扩容使用既有健康、容量和不同用户数分配规则。同用户同模板不得重复占用；未支付订单预留继续占库存且保持下单实际数量快照。
- 先保留所有实例的现有节点，再按开通时间补缺，避免先处理的实例抢走后续实例节点。缺额仍保存完整目标；后续增加模板候选节点时沿用保存流程补齐自动实例，也可再次点击应用重试。
- 定制实例保留原自选节点，目标沿用配置数，不受后来新增的自动候选池大小影响；已开通定制实例可从当前模板池补缺。待开通实例只更新目标，仍由管理员完整选点并开通，不提前开始计时。空池没有可补资源时报告缺额，不能把定制目标降为0。
- 同时在线、带宽、流量和启用状态沿用现有实时模板规则，保存时已生效；应用再次执行租约与限速协调。移除节点、超出同时在线数、额度不符的租约会撤权，Agent 下一次同步停止转发；控制端校验即时采用新配置。
- 不重置用量、预留预算、付费周期、到期时间、订阅 ID 或导入 URL；修改套餐价格和有效天数不追溯改写已付款订单／周期。新节点在客户端下一次更新订阅或原生同步时可见。

## 事务、幂等与性能

单个数据库事务完成分配、订阅／用户版本更新及租约协调。先按用户 ID 顺序锁用户，再写订阅和租约；并发购买、编辑和再次应用由既有 Serializable／SQLite 写事务及明确回滚重试处理。完整分配重放不再增加订阅版本；缺额重放允许在资源恢复后继续补齐。业务审计记录操作，不存诊断证明、物理路径或导入历史。

每次显式操作读取一次当前库存快照、处理这个模板的当前持有者，无定时任务、外部请求或新增轮询。复用既有额度查询及租约协调；大批量持有者的事务成本随实例数增加。没有 schema 迁移。发布须同时更新控制端与管理员站；新入口不适用于旧控制端。
