# host-network v1

Owner: `host-network`；`internal/hostnetwork`、Agent 持久化队列、store 主机账本。
Consumers: 管理员节点列表、节点详情、服务器详情。用户订阅不消费此数据。

Request/event: Agent 每 5 秒独立采集 Linux 物理／虚拟机网卡的累计 RX/TX，通过既有上报携带至多 8 份 `hostNetwork` 快照。`bootId` 与网卡 `ifindex` 标识同机各 Agent 共同观察的内核计数。仅控制端 `hostNetworkVersion=1` 时发送，未确认记录留在本地 FULL-synchronous SQLite 中。采集先于代理采样，HY2/VLESS 故障不停止网卡采集。

Response/handling: 管理员 `hostNetwork` 返回整机已观测收发累计、最新各网卡计数、首次采集时间、新鲜度与重启／计数器重置标记。相同服务器的不同节点展示同一份主机总量，汇总必须按 serverId 去重。服务端以服务器汇总行先加锁，再更新每次启动的计数水位；重复、乱序、多 Agent 上报不重复增加总量。重启后保留旧累计，首次快照计入当前启动已有计数，不伪造流量发生日期。

Errors: 缺少网卡、读取失败、不支持的平台显示未知或保留过期累计；不能显示为 0。非法身份、负数、溢出、过量接口／样本拒绝整个报告。上报成功但回包丢失可安全重放。平台采集失败不影响代理服务。

Limits and side effects: 最多 64 个采集接口、256 个排除接口；单次启动最多 256 个曾观察到的网卡索引。复用原 5 秒上报，无新浏览器轮询。稳定运行时本地仅保存最新快照及一个待确认快照；离线重启、计数器重置或网卡移除时保留额外检查点，按每批至多 8 条排空，不能为限制条数静默删除未确认数据。中央每次启动保留去重水位，管理员节点列表只增加一次批量查询；服务器监控每次增加一次主机键查询。数据仅是业务计量状态，不含密码、物理素材路径或运维操作证明。无数据库结构迁移，扩展采用既有键值业务状态；旧订阅与节点代理账本不变。

Compatibility: 先更新控制端再更新 Agent。旧 Agent 的网卡字段缺失表示尚未采集。网卡累计独立于 1.5 倍订阅扣量，也独立于节点有效载荷累计。上传／下载表示用户视角时沿用代理用量；网卡明确用接收／发送，避免混淆。

Examples: 用户下载 1 GB，节点有效载荷约 1 GB，订阅扣量 1.5 GB；服务器网卡同时承载代理入口与出口，RX＋TX 通常超过 2 GB，此外还包括系统更新、SSH、DNS、同步、其他服务及重传。

## 可证明的范围

网卡统计排除 loopback、bridge、bond、VLAN、veth、TUN 等虚拟转发层，只计物理承载网卡，避免重复。只提供容器 veth 的主机暂不支持，显示不可用。Linux 驱动计数与厂商账单层级可能不同；没有独立采集记录的旧周期不能补造。重启／驱动重置前最后一次持久化采样后的流量无法证明完整，明确标注断点。

同一启动内的正常单调计数支持乱序、多 Agent 去重；发生重置时保留本地重置前检查点并按 UTC 纳秒时间顺序补报。多个 Agent 跨重置乱序时，已被更新水位越过的旧检查点无法可靠归属重置代次；不能据此承诺重置前历史无缺失。计数器回退、接口集合变化和启动变化均标记累计存在断点，待接口集合稳定后恢复正常速率。网卡统计是可观测下限，不承诺等于厂商账单或绝对零遗漏。

系统自身、其他进程和协议开销已经包含在总量中。当前生产未开启进程级网络计量，**不能用网卡总量减节点有效载荷、或减两倍有效载荷来声称精确的系统自身用量**。管理界面将该独立分项标为未分类，不把未知量写为零；历史上这些分项无法还原。
