# 网站、客户端与节点性能和稳定性维护

日期：2026-11-23。范围是当前 HQIP 工作区的源代码及本机隔离测试。
开始时已有 Godot/Android 客户端、VLESS 独立出站、公共守卫及部署相关的未提交工作；本轮保留这些内容，只列出本轮新增改动。未部署生产服务，未修改生产域名、证书、Reality 身份、节点端口、系统代理、路由或 DNS。

## 已复现的问题与处理

| 所有者 | 原行为 / 复现 | 本轮行为 | 边界 |
| --- | --- | --- | --- |
| client-presentation / 两个网站 | 通用读取钩子每隔 5 秒发请求，前一请求未完成仍会继续；两个周期加两次可见性事件共发出 5 次读取 | 每个钩子只有一个在途读取；本例为 1 次 | 不跨账户、路径、组件缓存敏感数据 |
| client-presentation / 网站刷新 | 提交后刷新与旧读取并行，旧响应可能覆盖新状态 | 合并为一个后续读取；有后续刷新时丢弃旧结果；调用者等待后续读取完成 | 不重放 POST/支付/修改订阅 |
| client-presentation / 登录状态 | 旧读取在消费 JSON 时被取消，随后收到的 401 仍触发退出登录事件 | API 在处理响应副作用前再次检查取消信号 | 当前有效请求的 401 继续走原退出流程 |
| client-presentation / 内核指标 | 每秒请求 `/traffic`、`/connections` 和代理 gRPC 统计；`/traffic` 结果未使用，失败却会使整个采样失败 | 去掉 `/traffic`，正常每次采样由 3 个本机请求降为 2 个 | 速率仍从代理累计计数计算；不混入直连流量 |
| node-metering / Agent 同步 | 每轮先 GET 配置，再 POST 流量，而 POST 已返回同一配置类型 | 正常轮次只 POST，并应用返回配置；这两个控制请求由 2 次降为 1 次 | 失败、退避及账本错误仍走 GET，累计用量确认与撤权规则保留 |
| protocol-outbound / VLESS TCP | DNS 有多个地址，只连接第一个；本机 DNS fixture 的首地址拒绝时，第二个正常地址从未被尝试 | 一次解析、逐地址校验、有限备用连接；首地址故障时可连接正常地址 | 不重放应用数据、不放宽私网拒绝、不改变节点源 IPv4 |

请求数变化是上述具体路径的计数，不是全系统请求下降比例、吞吐提升比例或生产 RTT 改善承诺。新代码不增加远端测速端点、周期带宽下载、节点轮询或自动协议切换。

## 调度与资源契约

`web-shared/polling.ts` 只有读取任务的调度，不引入 React 依赖或共享业务状态。用户站与管理站各自持有 API、CSRF、鉴权和界面状态，仍可分别安装依赖和构建；构建需要同一仓库中的共享源码。现有 CI 对两个网站完整构建，已覆盖该目录的消费者。

- 在上次读取结束后才开始计算下一轮间隔。读取 15 秒超时取消；后台不启动自动轮询，返回前台可立即恢复。
- 请求失败保留上次数据，轮询退避翻倍，最多 60 秒；原配置间隔大于 60 秒时保留该间隔。
- 人工刷新 / 写操作后的刷新可唤醒轮询，但同时出现的刷新只合并为一个后续读取。
- 页面卸载或路径改变取消旧请求、清除定时器和监听器；过期响应不能更新新页面或触发登录失效事件。
- 各页面已有的支付专用轮询保持原有幂等恢复契约；本轮没有把所有业务轮询强制统一为同一规则。

VLESS 出站 DNS 解析仍最多 4 秒，与 TCP 备用连接共用 10 秒总预算。最多保留 16 个经过 ACL 检查且去重的 IPv4 候选，同时拨号不超过 2 个；第二个连接在首个失败或等待 250 毫秒后启动。首地址保留剩余总预算，中间备用地址最多 3 秒，最后候选使用剩余预算，避免缩短单地址弱网连接的等待时间。最快成功的一个连接交给调用者，其他尝试取消，迟到的成功套接字关闭。首地址快速成功只建立一次连接。UDP 仍选择单个目标并使用原有有界缓存，不复制 UDP 数据报。

Agent 的正常配置刷新周期仍为 5 秒，流量确认成功后仍按既有规则持久化确认，再应用返回配置。上报异常时的配置读取不被流量退避挡住。新收到的退休命令由原退休状态机推进；进度报告仍以已完成的本地状态为准。没有增加业务表或在数据库保存分析证据。

## 延迟、第三方订阅与大陆可达性

本轮没有降低显示数值、取历史最小值、把失败显示为 0、把未鉴权握手当作成功，或在节点上伪造测速 URL 的 204 响应。

当前原生节点列表测试测量经过验证的 QUIC/TLS 或 Reality 握手，不占代理名额；现有实现已排除 DNS 与排队等待，按物理出口拨号、端点去重、最多三个节点同时测试。仪表盘的 HTTPS 测试则穿过实际代理路径，含实际协议与目标站开销。这两种口径不能直接比较，也不能通过统一压低数值解决真实线路问题。

门户完整 Clash 和 sing-box 订阅目前使用选择器；节点 URI 只携带节点参数。第三方软件的人工测速 URL、并发数、超时、是否重新建连与历史结果展示由软件自身控制。服务器侧的 VLESS 多地址修复对它们同样生效，但不能通过 URI 强制所有软件显示相同延迟。原订阅认证、Reality 的 Chrome 指纹 / Vision 能力选择、域名及密钥保持不变，无需为此轮源代码修改重新生成用户凭据。

复查保留了现有管理请求的物理网络直连、HTTPS 校验、多地址 TLS 竞争、GET 有界重试、写请求不盲目重放、授权暂时失联时不误退登录，以及 HY2/VLESS 独立出站等边界。这些是当前代码的容错机制，不是 GFW 不会封锁的证明。

本机网络不能代表大陆电信、联通、移动。缺少三网实际多时段样本，不能给出抗封锁或固定低延迟承诺。未盲目替换 SNI、端口、加密参数、域名或 Cloudflare 配置，也未用高频主动探测制造额外流量。当前 HY2 配置使用内核默认的未鉴权 HTTP 响应；单独改成统一静态首页不能证明抗识别能力，需与实际部署入口和目标兼容性一起验收。

上线前应使用受控账号对同一节点、同一时段记录：连接成功率、握手与实际 HTTPS 延迟的中位数 / P95、断网恢复耗时、长连接稳定性与有限字节下载吞吐。区分冷连接和已连接状态，不把目标站限流 / 拒绝误认作节点失败。此步骤属于待执行的大陆线路验收，本轮没有伪造测量结果。

## 验证与已知限制

- 新网站回归在修改前复现请求重叠、无取消、无退避；增加取消后鉴权竞态用例也先复现再修复。用户站测试包含两个实际 API 钩子的受控 fetch/定时器测试。
- 新客户端测试在旧代码下因 `/traffic` 返回 503 而采样失败；修改后只请求连接摘要和真实格式的代理 gRPC 统计。
- 新 Agent 测试在旧代码下观察到 2 次 GET + 2 次 POST；修改后为 0 次 GET + 2 次 POST，并应用最新配置；既有上报退避 / 待确认用量 / 撤权回归保留。
- 新出站测试通过本机 DNS 返回两个地址，旧代码仅报首地址拒绝；修改后抵达第二个监听器，并保持节点源地址。其他用例验证黑洞备用连接、并发上限、首地址成功无备用、取消关闭迟到套接字、失败候选不重试。
- 全包回归首次暴露原有 `TestNodeProbeDomainReachesTransport/reality` 的 Accept 调度竞态：拨号已成功但监听协程尚未发送确认，非阻塞断言立即失败。本轮改为在原两秒预算内等待确认；仍要求未鉴权监听器不能通过 Reality 校验，连续 10 次回归通过。早期失败没有被记为通过。
- `go test -tags=with_utls ./...` 和 `go vet -tags=with_utls ./...` 通过；Agent、client、outbound、Reality 包完整 race 检查通过。
- 使用 `dist/godot-windows/versions/bundled/sing-box.exe` 执行代理累计统计、隔离 HY2 丢包恢复、Reality/Vision 真实互通测试，通过；测试不接管系统代理或 TUN。
- 用户站 24 项测试（包含两个网站的 12 项通用轮询回归）、管理站原有 24 项测试及两个网站生产构建通过；Linux amd64 Agent 编译通过。管理端仍有主 JS chunk 大于 500 kB 的构建提示。本轮没有调整路由拆包或声明首屏性能已经全面解决。
- 未运行生产并发压力测试、Android 真机 TUN、大陆三网、真实 PostgreSQL/Redis 专项环境或生产升级。根模块默认跳过依赖专项环境变量的测试，不能将跳过项算作真实验收。
