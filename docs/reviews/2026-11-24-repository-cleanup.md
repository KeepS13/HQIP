# 仓库旧代码与冗余清理（2026-11-24）

范围为整个 HQIP 仓库的源码、前端入口、构建发布链及本地产物。开始时已有大量未提交改动；本轮基于该工作区继续维护，未重置、提交或部署这些改动。历史事故记录、用户状态、签名身份和上游来源记录保留。

## 已删除

- Go：无调用的证书指纹函数、客户端同步错误包装、两个未挂载的订阅申请处理器、旧单实例 systemd 模板，以及失效的测速测试 transport 和登录测试字段。Windows 和 Linux 的 U1000 结果一致确认这些符号未使用，图分析的 UNKNOWN 结果另经文本检索核实；当前 Store 操作、路由和每实例部署逻辑保留。
- 前端：孤立的 `DeleteDevice.tsx`、`SelectionMenu.tsx` 及后者专用样式；用户网站复制自管理端的整份旧 `src/types.ts` 和 11 个无消费者的辅助组件/函数；管理端无消费者的成功图标、设备详情模型、门户类型和地址常量；用户端无消费者的人机验证配置类型。TypeScript 导入/引用检查包含静态和动态 import，保留真实使用的图表懒加载、再导出和模块内部引用。
- 旧恢复 UI 测试对已删除管理页面的读取；保留且重新运行真实桌面组件渲染断言。相关历史验收文档注明适用版本，避免误把旧行为当作当前保证。
- 忽略规则中不存在的旧 `web/` 路径及重复 EXE 规则。诊断目录 `/.diagnostics/` 加入忽略，现存证据没有删除。
- 签名更新目录中 46 个不再被清单引用的包，共 **5,695,757,930 字节**。先验签并验证保留包，再按摘要验证所有删除候选，最后执行精确文件/空目录删除。
- 旧便携 ZIP、4.6.0 Windows ZIP 及配套清单、已被 `versions/bundled` 取代的平铺运行时，共 **141,333,884 字节**。删除前核对当前交付清单、旧包摘要及实际进程路径。

本地旧产物合计回收 **5,837,091,814 字节（约 5.44 GiB）**。保留 preview.16 的 EXE、两个架构 APK、内部 Windows 更新 ZIP，以及每个平台 preview.16 / preview.15 的六个签名渠道包。

## 避免再次堆积

`cmd/hqip-client-release/prune.go` 归属客户端发布工具，沿用 `client-runtime.updates v1` 的每平台两版本保留契约。发布清单成功后自动回收；独立 `-prune` 只用公钥预览，`-prune -apply` 执行。校验整个保留集合与候选集合后才删除，不递归删除，不删除未知内容或跟随目录链接；失败可以重试。独占发布者约束、性能和使用方式见 [安装与更新](../applications/client-installation.md)。

新增生产代码少于 300 行。用户网站公共组件从 583 行缩至 375 行，作为 301–400 行的暂存例外，保留同一应用的公共展示/弹窗组件职责；本轮不为仅移除未使用代码拆分其他既有大文件。新增回收逻辑只在发布维护期间顺序读文件，不增加业务请求、后台轮询或数据库记录。

## 确认仍需保留的旧内容

| 内容 | 保留原因 |
| --- | --- |
| Wails `desktop/`、`build_desktop.py`、旧更新检查器 | CI Windows 打包、Windows E2E、完整发布校验和生产下载入口仍使用。下线需要同步迁移这些消费者，不能直接删除目录。旧本地产物可重建，已从当前交付目录清除。 |
| `internal/client/updates.go` 中版本与 HTTPS 校验 | 新 BundleUpdater 与旧桌面端仍有真实调用。 |
| 数据库/账号/账本迁移与回滚校验 | 保护现有业务数据、历史结算与既有部署回滚，年代较旧不等于无用。 |
| Windows helper 的共享声明 | Linux 单平台 U1000 报告四个“未使用”声明，但 Windows 消费者存在；跨平台误报不作删除依据。 |
| Hysteria 上游 BBR 代码 | 核心模块 U1000 报告七处上游未使用成员；保留上游可追溯补丁边界，不把第三方实现改造成无来源的删减分支。 |
| HY2 billing 适配及测试 | 旧导入路径向 nodepolicy 转发，重复的边界测试仍检验两个公开入口。 |
| SDK、构建缓存、品牌资源、许可证、诊断与签名目录 | 有实际构建/合规/故障分析用途。尤其 `.local/godot-signing` 是持续发布身份，不能作为缓存删除。 |

## 验证与边界

- `go test -tags=with_utls ./...` 全部通过；包括 Agent、控制端、Store、客户端和发布工具。
- 根模块 Windows U1000、桌面独立 Go 模块及 nodepolicy U1000 通过。Linux 仅剩上述四个 Windows 专用声明；Hysteria 核心仅剩上述七个上游成员。
- 管理网站、用户网站、桌面前端三套生产构建通过；网站 24 项测试、桌面恢复 UI 渲染和五项 Windows 安装打包边界测试通过。管理网站仍有既有的超过 500 kB 构建块提示，不影响本次构建成功。
- 回收测试覆盖三平台当前/上一版本、干运行、幂等、错误签名、错误公钥、空/坏清单、缺包、保留包/旧包损坏、未知文件。Windows 普通 symlink 单元测试因系统权限跳过；另以实际 Windows junction 完成孤立目录、保留目录拒绝及三次 CLI 发布自动回收验证。
- GitNexus 修改前逐项检查：公共管理类型文件为 HIGH（18 个直接导入），通过类型级引用确认后仅移除无消费者声明；用户公共辅助函数为 LOW/UNKNOWN，仅互相引用的死分支一并移除。发布函数和入口为 LOW，影响仅为本地发布过程。UNKNOWN 均未直接视为“无用”。
- 完整重建后，新增回收入口影响为 LOW；循环依赖检查枚举完整，结果为零。全工作区变更检测报告 70 个已跟踪文件、158 个符号及 CRITICAL 综合风险，其中包含本轮开始前的大量服务端/客户端修改，不能视为本轮独立清理的完整发布结论。检测限制从 5,000 提到 10,000 重新执行后结果相同；CLI 仍只展示部分符号/流程，索引器也明确提示流程枚举上限和跨语言字段遗漏，因此没有将其声明为全图无风险或用未显示的调用证明代码无用。
- 清理后再次只读验签及文件校验：保留六个渠道包，零删除候选；当前 preview.16 的三个用户交付文件均与 `godot-build.json` 的尺寸和 SHA-256 一致。
- 不涉及生产上传、域名、账号状态或密钥变更。客户端线上更新渠道尚未部署，不能把本地清理和打包验证当作线上更新验收。

操作证据位于库外：`.local/redundancy-prune-plan.json`、`.local/redundancy-prune-result.json`、`.local/redundancy-obsolete-artifacts.json`、`.local/redundancy-retention-validation.json`、`.local/redundancy-impact.txt` 及前端引用审计结果。它们不进入业务数据库。
