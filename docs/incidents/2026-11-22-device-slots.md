## 根因与修复

Agent 将任何授权截止缩短判为协议错误，设置拒绝状态并保留原 pending。控制端按幂等要求返回原回执，节点再次拒收；后续 final 和 release 无法越过旧报告，因此已结束连接一直占用至订阅到期。另一个同类边界是已提交报告的回执到达时过期：它仍是有效结算回执，却被当作新的转发许可校验而拒收。

`offline_receipt.go` 明确分离结算回执校验与当前转发资格。截止缩短及迟到回执可以推进账本，身份、用量、协议、版本、额度与名额确认继续校验。转发仍受当前期限、撤销、拒绝状态及名额约束。已卡住的账本升级后原样重放，再正常 final/release；不清空账本，不伪造未知流量。

同时修复控制端空闲父授权的期限刷新：合法的节点额度报告（含 release/acquire）同步最新本期终点及会话截止，避免重新连接获得旧离线有效期；已释放名额不会因刷新重新占用，过期或撤销授权不复活。

## 追加排查：其他名额残留路径

用户继续要求排查其他误占用来源后，新测试在原实现上复现两处独立故障：

- 首次授权已经在控制端提交，但节点未收到回包；节点只存 `offline_requests`，周期任务却只遍历 `offline_grants`。用户不重连时，中央占用没有恢复及结算入口。
- 同步每轮固定按父账本 ID 排序，前面的网络请求耗尽四秒总预算后，后面的已结束连接无法得到处理。测试把每轮预算限制为一次成功请求，连续四轮后原实现仍只处理第一条，后一条没有释放。

修复增加节点鉴权的只读回执恢复接口，按原请求 ID 查询，保留凭据、协议和来源 IP 绑定。后台仅对从未下发过子许可的零报告、零用量授权提交真实的零用量 final；已保存子账本和未知预算继续保留。缺少本地账本但中央已有用量时不能伪造零 final。回执不存在时继续保留原请求，防止原准入事务迟提交后成为无人回收的授权。恢复每 30 秒最多 16 条、按键轮转，最多占用同步剩余预算的一半；正常报告按最早重试时间调度。

同时封住相邻的崩溃边界：父账本已保存但请求标记未删除时，后台恢复和客户端重试都不能以空账本覆盖已有子连接。首次回包截断、先丢回包再因凭据轮换被拒绝、迟到的初始过期回执，也都保留可结算状态。退役流程不能跳过这些待确认请求。恢复不依赖明文密码，不新增数据库表或改动原来的 HY2/VLESS 计数方式。

崩溃覆盖及截断/后续拒绝的回归也通过 Go `-overlay` 对照仓库原版准入函数复现失败；overlay 仅用于测试编译，没有回滚或覆盖工作区源码。原版会复用忙碌的父账本，且删除两类不确定请求的恢复标记；修复后的对应测试均通过。

换节点、显式撤销、异常子连接结束和跨协议计数也已复核：已撤销但尚不能证明停止转发的授权仍短暂计入占用，这是离线安全边界；节点确认 final、内核实例改变或完整单调租约结束后释放。来源 IP 去重仅适用于 VLESS，HY2 每个独立会话分别计数，登录设备列表为空不能单独证明代理会话为零。
