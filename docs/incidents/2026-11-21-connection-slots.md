# 2026-11-21 断开连接后的名额回收

12:56:23 UTC 生产检查发现：指定订阅的三份节点额度父账本报告均为 active=false，但连接名额有效期仍至订阅到期日。流量预留已在前一修复中解除，这次阻塞来自父授权与在线名额共用生命周期。

connection-slots-v1 将订阅身份及累计计量与在线占位分开。新 Agent 正常收到 final 后立即补报并释放；异常断开依靠核心终止或最后一次发放子租约后的单调时钟 125 秒证明，不再因同订阅另一连接在线而阻塞回收。核心状态暂不可读仍可使用单调期限证明。网站失联时保留已持有名额，恢复后补报、汇总并执行撤销或额度限制；已释放名额必须重新获得网站批准。

释放只清退在线占位与带宽份额，缺失 final 的流量预算仍保留；迟到 final 继续补账。满额的重新申请也确认真实累计流量，返回未获名额，而非回滚用量。已撤销的结束连接同样释放名额。

本地验证：Go 全量 race、vet 通过；新增边界回归通过。真实双节点单名额测试完成“节点一→节点二→节点一”，每次强制退出后由核心确认断开，随后占用归零，复用原累计账本和正确带宽。真实双节点网站失联超过 120 秒仍可转发，恢复后准确汇总。Windows Python 新兼容性测试通过，全量部署测试仍受既有符号链接权限与路径差异影响，Linux 全量以 CI 为准。

发布须先控制端再节点，记录 capability 与业务版本，升级和回退前后均检查账本兼容性。生产验收需确认 15 节点 connection-slots-v1、目标订阅实际代理与断开回收、默认 1.50 倍率及真实流量未被清空。部署与线上证据补记于此；库外日志位于 .diagnostics/ntt-20261121/。
