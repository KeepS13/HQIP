# 2026-11-21 有限流量订阅准入故障

## 根因

离线父授权活跃上报时，补额算法反复领取剩余余额，却未扣除自己已经持有的未用预算。升级协议计费后，新 HY2 / VLESS 请求又不能复用无协议的旧父授权。两处叠加，使有限流量套餐被预留锁住；不限流量的「全部ip」没有有限额度预留，因此不触发同一故障。

2026-11-21 10:23:42 UTC 的一致性数据库快照中，指定订阅 `Xr-z3ShXNznvWIf3DJ` 的总额为 1,000,000,000,000 字节，已用 44,761,700,397 字节，预留 955,238,299,601 字节，新连接可申请余额仅 2 字节。实际有约 955.24 GB 未使用。并发上限 3，当时只占 1 份，最初拒绝并非并发超限。

当时全站有 54 份订阅、53 个账户符合“总余额至少 16 KiB，但扣除预留后不足 16 KiB”。这是新授权阻塞的数据库判定，不表示每个既有连接都已中断。计费倍率开关当时关闭，故这次事故不是 1.50 倍率导致。

## 紧急恢复

修复提交 `c21a484df2267cf7925f9ead606901ae1efd5aaa` 已通过 CI run `44897453015` 的 Linux、Windows、PostgreSQL 和部署检查，并成为控制站正式版本。

- 补额只填补当前授权合理份额的不足，反复零用量上报不再持续蚕食其他名额的余额。
- 旧父授权的所有子连接明确 final 后，先持久化禁止复用，再按原样重放待确认报告，最后正常结算父授权。
- 指定订阅旧父授权 `NFQYlOEH8B8dtZnkJ9` 的 5 个子连接均明确关闭且内核在线数为 0。通过正式撤销与 Agent final 释放预留，没有修改真实用量或直接清零 reserved。
- 真实代理四条路径已验证：zus2 的 HY2 / VLESS，itp0 的 HY2 / VLESS，出口均对应实际分配节点。
- 14 个生产节点均完成该 Agent 升级，回执确认 HY2 转发核心没有重启。itp0 的自动传输失败后，通过校验主机指纹的 SSH 上传同一正式产物完成持久化升级，操作号 `e00bba56914b47ec81`，产物 SHA256 为 `0ef8c08d6996006154f925e59698d733859882c258eb84928c18d23c16d3191a`。

## 旧授权安全迁移

2026-11-21 11:52:35 UTC 复查仍有 49 份订阅、48 个账户符合预留阻塞条件，31 份无协议旧父授权未关闭。节点账本显示其余旧子连接缺失 final；不能把超时、Ended 或内核重启当成精确最终计数。

后续节点额度版本增加安全归还路径：节点确认旧传输结束、持久化禁止复用后，上报 retainedNormalUnits。该数值为已关闭子连接的真实用量，加上未知子连接的完整已委托预算。中央只归还从未委托给子连接的部分，保留未知预算并接受迟到的真实 final；同时到期旧父授权的连接名额。它不清空账本，也不伪造旧连接的最终用量。

新 `node-quota-v1` 契约让同一节点同一订阅的 HY2 / VLESS 共享套餐总余额，在节点 SQLite 持久化计算。网站接收累计用量和确认水位，不再为新父授权切分流量。网站失联时按最后同步余额和倍率继续；用户已明确同意多节点失联期间可能合计超额，恢复后汇总停用。详见 [节点额度契约](../contracts/node-quota.md)。
