# 未连接节点即时切换与仅手动测速

日期：2026-11-24。版本：`5.0.0-preview.11` / `5000011`。

## 问题与修复

1. Go 已使用纯本地事务保存未连接选择，但界面仍等回执后才显示，延迟来自展示链路对保存/管道响应的依赖。`main.gd` 的 pending 判断还会直接丢弃期间的新点击。
2. 仪表盘节点名取 `desired*` 对应的目录项，套餐小字和摘要却取 `subscription` 授权字段；遇到新选择与旧授权同存的快照，会显示不同组合。
3. 登录后后台 Run 在首次成功同步后仍调用一次自动目录测速。上一版只是将仪表盘手动按钮限制为单节点，未删除该独立自动入口。

新增 `runtime/local_selection.gd` 管理展示草稿。未连接点击后立即从缓存目录投影完整选择，原生确认快照保持独立；单个在途保存串行，快速点击只保留最后一个待保存目标。当前失败恢复最后确认的完整组合，过时回执/错误不能闪回旧选项。已确认相同选择不重复写入。确认前只暂时禁用连接和当前节点测速，不显示连接加载。弹窗先关闭再发出选择信号，避免关闭前重新布局列表。

仪表盘节点标题、套餐小字和摘要统一按 desired subscription ID 查询目录。过时状态响应直接丢弃，不再额外发状态请求。删除自动测速方法、运行循环调用、标记及退出清理字段；保留手动全目录、当前节点及已连接代理延迟入口。

## 回归证据

- `instant_selection.gd` 在修改前复现 8 项失败，包括显示滞后、旧轮询覆盖、连续点击丢失、旧回执闪回和套餐身份混用。修改后通过：模拟运行时迟迟不回执，在实际节点按钮回调内即断言三个区域已同时改变，不依赖等待帧或轮询。
- 同一测试覆盖快速多次切换、失败回退、过时错误、重复选择、退出后迟到回执；发出的命令全部为 `node`，没有测速、连接、刷新命令。图形运行的点击处理约 5.7ms，仅为本机夹具处理时间，不代表所有设备的端到端延迟承诺。
- 原生 `manual_probes_test.go` 驱动三次真实运行循环、后台同步和本地选择，排空任务后探测计数为 0。另一个用例反复切换 40 次，检查原生快照中的套餐与节点一致，确认 0 账户 HTTP、0 内核调用、0 探测；显式手动测速才增加一次探测。
- `go test -race ./internal/client ./internal/clientbridge ./internal/rules`、Windows 适配器、原 Wails 测试通过。原有交互、订阅/单节点测速、七种窗口宽度与几何、无原生桥的 UI smoke 全部通过。
