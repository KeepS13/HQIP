# 自动切换与当前连接延迟

日期：2026-11-24。用户在 preview.12 验证后调整要求：已连接时选择节点需自动断开旧连接并连接新节点；每次连接成功后自动显示当前连接延迟，其余测速手动触发。本记录替代上一版对应交互约定，不撤销账户同步和界面响应优化。

## 行为与所有权

Godot 继续在点击内立即显示选择，保存命令不等待网络或连接锁。Go 控制器在保存成功后，仅对已有连接意图自动排队切换，旧连接/授权/恢复任务被取消。原停止、释放、等待关闭和连接流程串行执行。连续快速选择只允许最新待执行目标开始连接；重复选择当前目标不重连。手动断开先撤销连接意图，阻止排队或迟到任务重新接通。未连接时选择仍只保存偏好，登录不自动连接。

同订阅节点切换复用已导入授权与规则；跨订阅才执行必要的授权事务。不恢复每五秒全量导入或自动列表测速。取消的订阅请求可能已在服务端提交，因此按当前 API 会话保留内存中的不确定状态，下一次连接重新核实 revision；选回原节点也不能直接使用旧缓存授权。无效节点、保存失败或连接失败不自动回退其他节点。

每次连接成功及同节点恢复成功，异步测量一次实际代理连接的延迟，期限 5 秒；与手动延迟检测共用单任务约束。登录、普通刷新和重复选择不触发检测；失败不重试、不影响连接。切换/断开/恢复开始时清除旧值并取消旧请求，结果写入检查连接代次。列表握手测试保持手动，自动检测不遍历其他节点。Godot 的选点卡只在实际节点/订阅都匹配时展示当前代理延迟，实际连接卡也显示结果。

契约更新于 [client-runtime](../contracts/client-runtime.md)。新增 `active_choice.go`、`connection_delay.go` 各自负责异步切换和当前连接延迟，均小于 300 行。已有 `recovery.go` 309 行保留恢复状态与终止顺序，为 301–400 行预算例外；没有新增数据库字段或外部依赖。
