## 迁移边界

本次是保留数据的主机和域名迁移，不是重新开空站。已有管理员、用户、订阅、订单、规则、节点、证书、加密支付配置及计量账本均保留，主密钥必须与数据库配套。不重新生成主密钥，不运行旧空站初始化或订阅开发数据清理流程，不改动既有模板价格；支付最低金额仍为 1 元。

旧主机 `207.57.127.105` 的三个 `5202345.xyz` 入口暂时代理到新主机。旧入口与新入口必须共用新主机的唯一控制中心和业务数据库，不能让两台控制服务分别写入各自的副本。暂留入口用于已有支付回调、订阅和客户端过渡，不能直接丢弃有效支付通知。用户应改用新入口，因浏览器 Cookie 不跨注册域名共享，需要重新登录。

## 切换前检查

1. 备份当前数据库、配套主密钥、运行配置、Nginx 与 systemd 配置，以及相关节点配置和账本。使用当前数据库类型对应的一致性备份方式；PostgreSQL 使用数据库备份工具，SQLite 使用备份 API 或停写后的完整快照，不能在写入期间仅复制主文件。
2. 新主机仅运行校验过的发布产物。预先配置三个域名的 DNS、有效 HTTPS 证书及自动续期，核对 Nginx 不影响其他站点。静态文件和公开下载包不能包含运行数据库、密钥或商户凭据。
3. 控制服务的用户来源、管理来源和公共 API 地址使用上表地址。两个前端支持 `VITE_API_URL` 和 `VITE_ADMIN_URL`；管理前端另支持 `VITE_USER_URL`，用于打开用户门户。环境变量必须在构建时设置，未设置时使用上述正式地址。
4. 在 Cloudflare Turnstile 组件允许域名中加入 `hqip.sharevps.online`，同步核对 HQIP 后台人机验证允许域名。Cloudflare DNS Token 与 Turnstile Secret 仍分别管理，不因迁移互换或重置。
5. 验证新主机能访问支付 FM 的 HTTPS 接口，再迁移已加密的支付设置；不输出密钥，不自动创建真实订单或付款。新订单的通知地址为 `https://api-hqip.sharevps.online/api/v1/payments/fm/notify`。

## 切换与验证

先准备新入口和发布产物，再停止旧控制服务写入，取得最终一致性数据并在新主机恢复。验证主密钥和数据后启动新控制中心，把旧入口代理到该中心。逐节点调整 Agent 控制地址并检查心跳、租约和用量上报；不要同时重置节点账本、内核计数或连接凭据。

检查三个域名的 HTTPS、直接访问页面与刷新、跨域登录、退出、CSRF、精确来源限制和 SSE；验证新用户域名的 Turnstile 与客户端浏览器授权。重新复制订阅和下载地址，确认它们指向新 API；已有自定义客户端服务地址保持原样。

对比迁移前后的账户、订阅、订单、已确认用量、待结算预算和基础设施记录；确认主密钥匹配、加密商户配置可读取、旧支付通知仍能到达同一个订单库。核对新客户端包的版本和校验和，并在节点正常报告后检查订阅准入。控制服务迁移期间要关注 120 秒租约限制；失联导致的停止需要用户重新连接，不能误称迁移全程无中断。

只有在核对旧订单的通知和结算状态、确认客户端与订阅入口已迁移后，才安排关闭旧入口。不要以等待固定几分钟代替检查，也不要把收到 HTTP 请求等同于付款成功；有效签名及订单核验仍由支付接口执行。

## 回退

回退前先停止新主机写入，保留最新数据库和全部新增支付、订阅、用量及预算记录。旧主机只能恢复与当前结构兼容的程序并接入这份最新数据；不能直接启动迁移前的旧数据库副本。节点地址、Nginx 路由和证书配置按配套备份恢复，仍保持唯一控制中心。

备份与恢复步骤参见[三域名部署与恢复](domains.md)和[支付配置与订单](payments.md)。迁移完成后保留受限备份及旧入口代理配置，后续删除另行确认。
