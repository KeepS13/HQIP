# 服务器与节点监控

服务器卡片汇总整台 VPS 的 HQIP 节点，点击任意卡片进入服务器详情。身份验证表示 SSH 主机身份已固定，运行状态取决于节点报告；两者不等同。列表可按名称、SSH 地址或公网 IP 搜索，并筛选异常服务器。

## 容量和流量额度

添加服务器时填写带宽容量（Mbps）、每周期流量（GB/TB）和北京时间整点到期时间；容量支持无限。已有服务器通过“额度与续期”修改，无需重新提供 SSH 密码。更换 SSH 管理地址仍需要验证原主机身份。

容量和流量额度仅在服务器层级配置，用于整台 VPS 的容量参考；周期用量达到 80% 和 100% 时分别提醒。修改额度保留已使用量，选择无限后隐藏百分比，计量继续。这些设置不会改变订阅授权、重启代理、限速或断网。

节点仅统计实际代理流量，不配置带宽容量或流量额度，不显示额度比例，也不产生节点容量预警。管理端展示节点上传、下载、本周期及累计用量；已配置有效期时，节点与所属服务器采用同一统计周期。历史节点容量字段不再生效，相关旧预警结束后保留历史记录。用户订阅自身的带宽、流量与连接限制继续按订阅执行。

GB = 1,000,000,000 字节，TB = 1,000,000,000,000 字节。月度历史仍按北京时间自然月计算上传和下载之和，累计用量不会清零。现有未配置到期时间的服务器暂按自然月展示，首次配置保留当月已用量，不猜测厂商到期时间。

## 到期与续期

- 新建默认预填 30 天后，可改为实际到期时间，不要求购买时间。未来刷新时间从最终到期时间按 30 天倒推，只安排保存时刻之后、最终到期之前的边界。例如填写 45 天后到期，会在 15 天后刷新一次；填写 95 天后到期，会在 5、35、65 天后刷新。保存时不因倒推出过去的边界而清空当前用量。
- 到期前确认续费按每月固定 30 天延长，从原到期时间累加，不立即刷新流量；未来刷新边界沿用同一 30 天网格。原最终到期时间在延长后也成为刷新边界。
- 最终到期时未确认下一次续费，流量继续累计，不自动刷新。到期后确认续费必须手动指定未来到期时间，确认时开启新周期，之后的刷新边界同样从新到期时间倒推。历史用量及用户订阅扣费保留。
- “修正到期时间”用于登记日期填写错误，未到期或已到期均可操作；只替换未来刷新边界，保留当前周期标识、起点与已用量。它与“确认已续期”分开：已逾期时确认续费会开启新周期，而修正日期不会。
- 在剩余 48、24、12 小时及逾期时生成后台运维预警。“确认已知晓”只确认预警；“确认已续期”才修改到期时间。
- 有效期和容量仅供管理员核对。HQIP 不因服务器到期停止服务器或节点，也不向用户发送提醒。

续期和日期修正都使用服务器版本检查与请求幂等键，网络重试不会重复延期或清零。所有确认及修正保留管理员、操作时间和前后到期日期，可在“续期记录”中区分操作类型。修正日期或确认续费都会结束旧到期提醒，新的提醒按新到期时间生成；单纯修正日期不会重置本周期额度预警的确认状态。

原生小时计量用于处理任意整点周期边界，不与分钟派生小时重复累计；节点离线补报按流量发生时段归属。旧 Agent、长期采样缺失或逾期确认所在的部分小时无法可靠拆分时，显示“用量数据不完整”，不把不确定旧流量算入新周期。完整历史累计继续保留。

数据不完整不阻断周期用量统计。服务器以已确认归属本周期的上传与下载合计除以服务器额度，正常显示使用率和进度；已知用量达到 80% 或 100% 时，分别产生提醒或严重预警，并附带数据不完整说明。节点展示已知用量并标注数据完整性。已有合计为零时按零计算，不补造缺失流量；服务器无限额度不显示使用率、不发容量预警。若已有服务器预警而后续不完整合计低于阈值，保留待核实状态，避免错误宣布恢复。

## 指标含义

- 节点的本周期、月度和累计代理用量来自代理计量账本，不包含内部连通性探测，不等于 VPS 厂商网卡账单；服务器上的其他应用流量不计入这组代理数值。订阅使用量按计费倍率扣量；节点代理值与整机网卡值均不乘倍率。
- 节点管理并列展示节点用户代理用量与所属整机网卡累计，并在列表顶部汇总当前筛选范围。代理用量逐节点相加，网卡按服务器去重；同机多个节点显示同一份整机网卡值，不重复计入汇总。服务器列表及详情也展示网卡总量。
- 整机网卡累计是 Linux 承载网卡的接收＋发送，包含两个代理传输方向、系统更新、SSH、DNS、管理同步、探测、其他服务及协议开销。排除回环及重复虚拟转发层。当前没有独立的进程归属账本，“服务器自身与其他流量”明确标为已包含、独立分项未分类；不能拿网卡总量减代理用量推算精确系统用量。
- 网卡首次采集导入当前启动已有计数，随后持久化累计，标为“已观测累计”，不是月度或服务器计费周期值。旧周期未采集的历史不能还原。重启／网卡重置可能损失最后采样后的尾部流量，界面保留累计并标注断点；旧 Agent、读取失败和超过 30 秒的采样分别显示尚未采集或过期，不能当作 0。速率同时受服务端与浏览器采样时间检查，停止刷新也会自动失效。
- 实时代理速率包含连通性探测。上传和下载分别从字节/秒乘 8、除以 1,000,000 转为 Mbps；服务器分别除以配置容量计算占用，节点直接展示实际速率。不把全双工流量相加作为单向带宽占用。
- 尚未确认停止的已安装节点应持续报告；只有最近 30 秒内且内核健康的报告参与实时汇总。缺失部分节点时显示已知合计和“数据不完整”，不显示确定的带宽占用率；全部缺失显示未知，不表示速率为零。
- CPU、内存、磁盘仅取一份最新有效主机报告，不累计同机多个节点重复报告。无有效报告显示未知。磁盘是 Agent 数据目录所在文件系统，并非所有挂载盘总和。
- “最近报告”是控制端收到报告的时间，不能视作独立的系统资源采样时间。页面请求失败时保留上次数据，并提示过期。

## 历史核对

网络总览和服务器详情提供按北京时间日期查询的代理流量统计，默认最近 7 天，可快捷选择今天、昨天、近 30 天、本月，或指定包含首尾两天的日期区间。查询限制在现有 13 个月日账本保留窗口内；没有采集的历史不会补造。今天的数字表示截至当前，包含今天的查询每 30 秒刷新，历史区间按需刷新。筛选写入页面地址，刷新与返回后保留。

区间总量、上传、下载、每日明细及服务器／节点贡献排行均来自同一份日账本聚合，不累加分钟派生小时或原生小时。日均以已记录总量除以所选日历天数计算，包含尚未结束的今天。缺少日记录显示“暂无记录”，有效零值显示 0；无记录不证明当日零用量或节点在线。离线补报会更新原发生日期，重复上报不重复累计。CSV 导出整个所选范围的每日原始字节数及记录状态。

总览在线用户按新鲜且健康的节点实际连接报告，通过订阅身份映射用户并跨节点去重；活跃订阅按订阅去重，连接实例逐个累计，均不含内部探测。网页／客户端登录及未关闭租约本身不算在线证据。身份无法映射的连接单独提示，不猜测用户数；部分节点缺失显示已知下限，全部缺失显示未知。

实时卡片分别展示上传和下载，使用 B/s、KB/s、MB/s、GB/s 自动单位，保留现有含探测口径，不能与日账本扣费量混用。每 5 秒刷新，并显示最近一分钟采样走势和控制端最近收到有效报告的时间；采样缺口留空，健康的零速率显示“当前空闲”，刷新失败标记过期。

节点贡献表列出各 IP 节点的本周期和累计用量；已删除节点单独列为历史贡献。删除节点、设备或 IP 清单不会抹除账本。同 IP 重新部署使用新节点 ID，新旧账本分别累计，补报按原计量映射归属。详细数据沿用现有保留周期，累计用量保存在独立账本。

流量补报按小批次逐步排空：Agent 每轮最多发送 500 条分钟记录及 500 条原生小时记录，日累计保留原有 4000 条容量，并与分钟记录分别取批，避免大量持续变化的日累计挤占分钟补报。服务端仍兼容旧 Agent 每类最多 4000 条的请求，按最多 128 条一批读取和写入，只将增长差额计入派生小时与累计账本；未变化的原生小时桶不重复写入。小时覆盖水位仍以实际已完整传送的时段为准。

流量报告失败后保留本地待确认记录，按 5、10、20、30 秒上限逐步退避，并加入 80%～100% 随机延迟；成功后恢复正常 5 秒同步。退避期间继续拉取配置、处理撤销和租约收尾。请求断开会取消未完成的上报事务；提交成功但确认丢失时，后续重复累计值仍不会重复计费。

正常同步直接应用流量上报响应携带的配置，不再在同一轮额外 GET 相同配置。上报失败、退避或本地账本确认失败时仍使用配置读取接口，避免用量故障挡住撤权。此优化只减少重复读取，不降低配置同步频率或丢弃待确认计数。

## 发布与回退

网卡扩展使用 `host-network v1` 可选能力，先升级控制端与管理站，再升级 Agent；不修改代理计费或订阅扣量，不新增数据库结构迁移。旧控制端不确认网卡扩展时，Agent 保留待补报记录。版本与语义见 [网卡计量契约](contracts/host-network.md)，本轮实现及未上线状态见 [检查记录](reviews/2026-11-25-host-network-audit.md)。

本次增加独立服务器周期与小时统计表，订阅 schema 保持 5。控制服务先兼容新上报，再逐节点升级 Agent；节点核心不需要更新。已有服务器不会因升级而被自动设置日期或清零。

现有 CI 先执行 Linux／Windows 检查，再通过 `scripts/upgrade_domains.py` 备份配套数据库、主密钥及站点配置并发布。发布包同时更新固定校验的 Agent 安装产物，HY2 等其余二进制保持原值。用 `scripts/upgrade_node_agent.py upgrade --node-id ID --artifacts /受校验产物目录` 更新已部署节点：先备份配置与 SQLite 账本，只重启对应 Agent，核对核心运行代次未变。备份目录权限受限，不提交 Git。

上线后检查小时统计能力、心跳、服务器与节点周期用量、历史贡献和预警。新版统计表初始化后，回退程序必须声明支持 `serverBillingVersion: 1`；即使尚未配置周期，旧控制程序也无法接收新增 Agent 报告字段，因此回退会被拒绝。此时应使用兼容周期结构和小时协议的修复版本。Agent 回退仅恢复服务程序路径，不覆盖最新账本或核心配置。任何恢复操作都不得用旧数据库覆盖新产生的用量。
