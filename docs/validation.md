# 首次上线验收记录

日期：2026-11-02（Asia/Shanghai）。目标：Ubuntu 22.04 amd64，约 1 GiB 内存；控制面与首个节点同机。实际管理员凭据、订阅令牌及测试运行数据未提交仓库。

## 已完成

- React/TypeScript/Vite 生产构建通过，依赖审计无已知漏洞；Go 全包测试与 `go vet ./...` 通过。
- 桌面浏览器实测登录、创建设备、节点表单与实时总览；390×844 手机尺寸检查，页面无横向溢出，表单可滚动；浏览器无前端错误。
- 自动 SSH 安装经实际网站 API 完成，安装二进制经本地清单与上传 SHA-256 双重校验，TLS 证书自动签发。
- 外部独立 Mihomo v1.19.32 成功校验配置、完成 UDP/TLS 连接，出口匹配登记公网 IPv4；完成 2 MiB 下载与 144 KiB 上传后观察到对应设备的用量增长。
- 正式订阅再次下载、解析并实际连接成功。用户现有 Clash 进程与配置保持运行，验收使用额外独立进程和临时目录。
- 两个独立设备凭据同时连接并分别传输 1 MiB，网站显示两个在线登记设备，流量分别增加。
- 额度设为 1 字节后出现 100% 超额提醒，代理仍可用；验收后恢复无限带宽和无限月流量。
- 停用设备后旧订阅返回 404，活动连接无法继续代理；节点确认撤销后重新启用可恢复。
- 轮换设备订阅与连接凭据后旧链接失效，新订阅成功连接。
- 停止控制面服务期间代理仍可传输；重新启动后自动补报期间产生的 3 MiB 下载量。
- 重启 Agent 后凭据仍可用，累计用量不重复；重启 Hysteria 后新流量正确叠加，不因内核计数归零丢失既有累计。
- 一致性数据库备份包含主密钥，在独立空目录成功恢复并通过数据库/密钥校验。
- 四个 systemd 服务 active；鉴权、统计、管理 API 只绑定 loopback；数据库、主密钥、Agent 配置均为 0600；剩余磁盘约 3 GiB。

## 自动化回归覆盖

认证、初始改密、CSRF/Origin、失败登录限流、Agent 权限隔离、凭据撤销、订阅隔离、计数重放/乱序/上海月界/保留期、部署并发编辑、SSH 指纹固定、恢复版本单调性、离线补报和队列压缩均有针对性测试。

首次实际安装暴露 SSH stdout/stderr 共用缓冲区导致输出丢失的问题，已改为独立缓冲并增加本地 SSH mock 回归测试。错误密码、无效输入及冲突状态使用单元/集成测试覆盖；未为测试而破坏用户服务器 DNS 或公网防火墙。

## 限制

Hysteria 2 需要客户端网络允许 UDP，不能保证在屏蔽 UDP 的网络可用。统计为代理有效载荷，突然内核崩溃可能漏掉最后一个采样周期；不承诺与服务商账单一致。在线数按登记凭据，不识别物理硬件。证书初次签发已验证，长期自动续期由 Caddy/Hysteria 原生 ACME 实现，未人为推进生产证书到续期日期。
