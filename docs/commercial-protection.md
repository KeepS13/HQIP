# 商用防护：源站、备份、登录与操作日志

三个正式网站只接受 Cloudflare 网段的原始 TCP 对端。Nginx 使用 `$realip_remote_addr` 判断来源，不能通过伪造 `CF-Connecting-IP` 或 `X-Forwarded-For` 绕过。HTTPS 直连源站返回 403；HTTP 仅 `/.well-known/acme-challenge/` 下合法单个 ACME token 文件允许直接访问，其他请求同样需经 Cloudflare。此规则只出现在 HQIP 三个准确域名的虚拟主机，不改变其他站点、SSH、HY2 UDP 或回环 18090/18091 探针。

安装和升级在启用规则前检查三个域名的 A/AAAA 全部解析到 Cloudflare 网段，并确认 HTTPS 响应来自 Cloudflare。首次启用按“新服务就绪、自动备份成功、重新核验 Cloudflare、启用源站限制”的顺序进行；期间保留原 Nginx 路由。DNS、代理或网络验证失败时保留原站点配置，先恢复代理再继续验收。网段来源保存在 `render_domains.py`，变更时同时更新生成配置、测试和部署。代理设置必须保持开启；不要在启用源站限制后直接改成 DNS only。

自动发布在释放发布锁后执行保护验收；手工 `upgrade_domains.py upgrade` 同样完成该流程。首份备份或代理验收失败后，使用原状态目录执行 `upgrade_domains.py complete --state <状态目录>` 重试；新站对应 `fresh_deploy.py complete --state <状态目录>`。源站规则启用后会再次核验公网；失败恢复启用前的准确 Nginx 配置。操作日志迁移只新增独立表，激活失败允许恢复兼容旧代码、路由及定时任务，保留新表和实时账本，绝不恢复旧数据库覆盖新增业务。

`hqip-backup.timer` 按北京时间每天 00:00、06:00、12:00、18:00 执行；主机错过运行时，开机后补一次。首次上线在释放发布锁后立即执行一次并核对成功回执，不等到下一个时间点。备份任务不停止 API，使用现有应用数据库角色生成一致性 PostgreSQL dump，并打包配套 `master.key`。定时和重试任务互斥，也与发布锁互斥。失败 10 分钟后重试，最多两次，之后等待下一正常周期。

自动归档只保存在 `/var/backups/hqip-control/automatic`，目录 root 0700、文件 0600，**本机保存、不额外加密、不上传异地**。其中含有主密钥，应按整站敏感数据保管。本机损坏、丢失或 root 失陷时，这些备份不提供异地灾备保护。

归档检查 PostgreSQL 格式、成员清单、主密钥长度，并计算 SHA-256，成功后原子发布。备份空间预算为 256 MiB 安全余量加现存最大自动归档大小的 4 倍，覆盖 dump、最终归档与增长；数据与备份文件系统都须满足预算。发布安装仍使用独立的 3 GiB 空间门槛。

每次任务先清理创建时间已达 14 天的自动归档，正常约保留 56 份；空间仍不足时，从最早的自动归档开始逐份清理，每删除一份重新检查空间，足够后立即停止清理并备份。清理前校验最近归档的完整性和 SHA-256，并始终保留该恢复点，即使它已超过 14 天。仅剩最近一份仍无法满足预算时，停止本次备份并保留失败告警；最近归档损坏时拒绝清理。如果数据目录位于另一块空间不足的文件系统，不删除无法释放该空间的备份。不清理发布前快照、人工备份和其他目录；异常目录、符号链接和不认识的文件拒绝自动删除。

安全状态写入 `/var/lib/hqip-control/backup-status.json`；脱敏回执写入 `backup-events/`，控制服务只读并幂等导入操作日志。状态包含最近结果、下一次计划、大小、摘要和错误码，不返回密码、连接串或归档内容。回执同样保留 14 天。运维可通过 `systemctl status hqip-backup.timer` 和 `journalctl --namespace=hqip-control -u hqip-backup.service` 排查；未经授权不得从后台下载或恢复数据库。

恢复仍按 PostgreSQL 灾备文档在独立空库执行 `restore_postgres.py`，保留恢复安全锁并核对业务账本；不能拿旧快照覆盖正常运行的实时数据库。上线验收应完成一次真实备份与隔离恢复、确认 timer 已启用，并检查伪造转发头直连仍为 403、Cloudflare 网站访问及 ACME 续期不受影响。

## 管理登录

继续使用账号密码与 12 小时会话，不增加 MFA、验证码或修改配置时的再次认证。管理员登录单独使用 Redis 原子限流，不占用用户、支付和 Agent 的请求预算。IPv4 按地址、IPv6 按 /64 聚合；每来源 15 分钟最多 10 次登录请求，全局每分钟最多 30 次密码校验，最多 2 个并发密码计算。

来源在最近 24 小时实际密码校验失败达到 5、10、20 次时，分别封禁 1 分钟、15 分钟、1 小时。拒绝请求不增加失败次数、不延长封禁；登录成功清除该来源失败和封禁，不重置请求预算。限流返回 429 与 Retry-After，Redis 不可用返回 503。已有管理会话继续有效，不永久锁定账号。客户端应展示等待提示，不连续自动重试。

## 操作日志

管理端 `/operation-logs` 默认查询最近 7 天，提供关键词、操作者、动作、IP、方法、认证方式、结果、北京时间范围，以及 20/50/100 条分页。筛选条件保存在 URL。管理员接口为 `GET /api/v1/operation-logs`、`GET /api/v1/operation-logs/{id}`、`GET /api/v1/backups/status`；普通用户和公开 API 无权访问。没有下载备份、恢复数据或清空日志接口。

日志从新版本上线起记录，保留 13 个月，与备份的 14 天独立。旧业务审计继续保留，不推测旧记录的操作者或 IP。记录关键写操作、登录结果、支付处理、备份结果与运维终态；查询轮询、心跳、租约与用量上报不记录。任务提交与最终成功/失败分开记录，通过请求编号和任务编号关联，批量操作明确标示部分成功。

记录采用字段允许清单，只保留动作、对象、变更字段名称、业务结果等摘要。不保存请求或响应原文、查询参数、密码、Cookie、会话令牌、SSH/DNS/支付密钥或订阅链接。匿名失败和限流拒绝按来源、原因及 5 分钟窗口聚合，实际密码验证失败逐条记录。日志故障输出固定脱敏系统消息并进入预警中心，新增日志不会把已成功的业务操作改报失败。

## 迁移与验收

`migrate-operation-logs` 由迁移角色执行附加迁移，应用账号不获取 DDL 权限。初始化、旧备份恢复和发布完整性清单均包含新增表版本。新版本启动会核验日志 schema；此次附加迁移保留旧程序兼容性；启动失败可恢复旧程序、站点和定时任务配置，同时保留新增表与实时业务数据，不能通过还原旧数据库来回退代码。

首次上线应依次确认：发布前快照可用、附加迁移成功、新程序健康、自动备份首份归档成功、三个域名的 Cloudflare 代理验证通过、源站直连被拒。真实业务通知与节点连接使用正式域名；源站限制不影响回环探针。排查日志可按请求编号、任务编号或操作对象串联提交和终态。
