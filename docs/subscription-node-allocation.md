# 每份订阅的节点分配与库存

模板的 `nodeIds` 是候选池，`nodesPerSubscription` 是每份新订阅获得的节点数（1–1000，新建表单默认1）。`description` 是最多2000字的可选纯文本介绍，每个非空行在商城及确认购买弹窗显示为一条说明。已有订单保留下单时的介绍快照。

新开通只获得实际分配的节点；用户详情、客户端配置、凭据、准入和Clash、V2Ray、sing-box导出使用同一份分配记录。商城的 `availableCopies` 和 `availabilityReason` 按当前用户计算，库存不足时下单返回409，不能绕过页面购买。

分配按节点已分配的不同用户数升序、所属服务器剩余流量降序、服务器到期时间升序排序；完全并列才随机。有效订单预留计入人数。只分配活动、就绪、支持准入且30秒内健康有效上报的节点；缺少服务器、服务器到期或整机流量耗尽均不可分配。流量沿用整机计费周期统计，未设周期使用自然月，不限量视为无限剩余，无到期时间排在最后。

库存分配只读取候选池内的节点健康和所属服务器容量，不读取实时在线身份表；分配人数来自有效持有及订单预留。客户端自动选点另行读取在线人数，继续使用原排名规则。手动赠送事务在写完业务状态及审计后提交，完整展示结果在提交后读取，避免为了展示实时用量把新开通与其他连接的计量事务耦合。用户锁、幂等校验、版本校验及 PostgreSQL Serializable 隔离保持不变；数据库重试仍限于明确回滚的可重试错误。

同一用户在同一模板下的未到期、未撤销订阅及有效预留互不重复。不同用户或不同模板可以使用同一节点。流量耗尽、用户或模板临时停用不释放占用；到期或撤销释放。6个合格节点、每份2个，最多可同时持有或预留3份。

订单创建事务内选择并预留节点，支付平台请求在事务提交后执行。取消、明确创建失败或未付款超时释放；结果不确定保留到支付期限结束，已确认付款不因期限结束释放。付款开通原子转换预留。预留后暂时离线不重新分配。迟到通知若预留已释放，会重新检查库存，不能凑满则进入“已付款，待管理员处理”，管理员补足资源后重试开通，不自动退款。

修改每份数量仅影响新订单、新开通。修改节点池时保留仍在池内的分配和预留，优先按开通先后补齐已有订阅，再处理订单；不足时保留缺口，预览和保存响应的 `allocationShortfalls` 列出详情。后续节点池变更再次尝试补齐；单纯健康、人数、流量变化不重新分配。连接节点的推荐仍使用在线人数规则，只能在获分配集合内选择。

用户购买后，管理员可从用户详情的“修改节点”更换某一份订阅的节点。选择数量严格等于该实例已保存的分配目标，不能增减或用当前缺额覆盖目标；模板后续默认数量不参与此次校验。更换保留原订阅身份、额度和计费周期，旧节点待结算用量与新节点后续用量仍在原账本累计。完整操作及接口规则见 [用户订阅管理](portal.md) 和 [API 边界](interfaces.md)，无需新增表或迁移存量数据。

## 迁移与发布

1. 停止控制服务及写入，制作包含数据库和匹配 `master.key` 的一致性备份。不要对线上数据运行测试夹具。
2. SQLite在新版本启动时事务升级；PostgreSQL使用迁移账号运行新二进制 `hqip migrate-subscription-allocations`，通过 `HQIP_DATABASE_URL` 提供连接。若支付表尚未初始化，先执行 `hqip migrate-payments`。应用账号不需要DDL权限，新增表和序列需沿用现有迁移角色的默认应用权限。
3. 迁移新增 `subscription_allocations`、`payment_node_reservations`，写入 `subscription_allocations_version=1`。已有订阅按迁移时的完整模板节点池保存，保留历史重叠和原用量、凭据、到期时间。旧模板的初始分配数为池大小，空池为1。已有订阅占满池时，同用户暂时无法重复购买。
4. 历史未完成订单按下单先后尝试预留，数量取订单快照。无法预留的未付款订单关闭本地支付入口；已付款订单保留待管理员处理。迟到通知仍核验，不把关闭入口当作支付平台退款或撤单。
5. 使用新服务及两端页面启动，检查商城、模板预览和订单。迁移可重复执行，不覆盖已保存的分配记录。订单开通或重试不触发真实付款测试。

日常CI发布会在停服并完成冷备份后，以 `/etc/hqip-storage/migration.env` 的迁移身份执行上述迁移，再切换新服务；迁移前核实其目标与正式应用数据库一致。迁移报错或超时会保留数据和备份、拒绝启动不理解分配记录的旧服务，需向前修复并重试，不能把超时当作未提交。

新库初始化、SQLite转PostgreSQL和备份恢复包含上述表。运行时要求能力标记；发布清单及 `storage-info` 声明 `subscriptionAllocationsVersion=1`，发布/回退检查拒绝不理解分配记录的旧版本。不可手动切回旧二进制，否则其模板全量授权逻辑不兼容。代码回退应使用保留新分配语义的兼容版本，不能用旧快照覆盖新订单与用量。
